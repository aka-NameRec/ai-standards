# РЕШЕНИЕ: реорганизация memory и retrieval

Английская версия: [2026-09-18-memory-retrieval-reorganization.md](2026-09-18-memory-retrieval-reorganization.md)

## Status

Принято. Реализовано на ветке `rules-change/16-memory-retrieval-reorganization`, выпущено в 2.4.0.

Частично суперседирует слой ConPort решения [2026-08-24-knowledge-store-role-separation.ru.md](2026-08-24-knowledge-store-role-separation.ru.md); роли Basic Memory, Chroma и git сохраняются. Исходная задача: #16. Эпик-продолжение (фазы 6–7): #19.

## Date

2026-09-18

## Context

Три разные задачи были смешаны в одном инструменте операционной памяти: project memory (локальное накопленное знание, сохраняемое между сессиями), knowledge retrieval (извлечение только знания, релевантного текущей задаче) и code retrieval / code intelligence (поиск и анализ большой кодовой базы). ConPort — инструмент, нёсший первую задачу, — перестал развиваться, хотя его семантика (контекст/решения/прогресс/паттерны/связи/продолжение между сессиями) остаётся ценной и инструментально-независимой.

Наивное удаление ConPort стёрло бы эту семантику. Его сохранение оставило бы стандарты привязанными к заброшенному backend'у и сохранило бы привычку предзагрузки: накопленное знание попадает в контекст только потому, что существует.

## Decision

1. **Удалить ConPort полностью** — фичу, записи реестра, default-манифест, шаги развёртывания, фрагменты, шаблоны и живую документацию. Датированная история сохраняет упоминания с supersession-ссылками. Полезные семантические свойства переходят в инструментально-независимые правила, а не в механическую замену имени на Basic Memory.
2. **Ввести `retrieval-routing`** — инструментально-нейтральный policy-слой: retrieval до широкой разведки; включённую retrieval-capability обязателно учитывать; маршрутизация по информационной потребности, а не по привычности инструмента; retrieval — обнаружение улик; верификация на авторитетном слое; постепенная эскалация. Связующий слой над всеми retrieval-capability.
3. **Ввести `project-memory`** — инструментально-независимая локальная рабочая память в `docs/local/**` (по умолчанию в `.gitignore`) с фиксированной таксономией: `context`, `decisions`, `progress`, `patterns`, `investigations`, `handoffs`; политика записи (курируемое хранилище состояния, а не журнал исполнения), политика чтения (точечные запросы, никогда чтение всего дерева) и явный lifecycle продвижения в каноническую документацию. Лучше всего работает с `basic-memory`, но не требует его: возможность отделена от способа её поддержки.
4. **Сохранить области ответственности `basic-memory` и `chroma`** — Basic Memory остаётся retrieval-слоем над Markdown для канонического знания и локальной рабочей памяти; Chroma остаётся слоем семантического поиска по коду; их хранилища не смешиваются.
5. **Развёртывание становится capability-based** — `deploy-ai-knowledge-stack` превращается в `deploy-ai-retrieval-stack`, разворачивая только слои, включённые в манифест; гейт шаблона переходит с `chroma` на `retrieval-routing`. `sync-templates` получает защищённый маркером retire-механизм, чтобы переименованные шаблоны не оседали в проектах. Апгрейд со старых релизов предлагает миграцию ConPort → `docs/local` до правки манифеста.
6. **`structural-code-intelligence` остаётся экспериментальной** — фрагмент-capability без развёрточной инфраструктуры; включение в рекомендуемый стек ждёт evaluation A/B/C на реальных задачах.

## Why

- Семантика памяти доказана использованием; ценностью был не backend.
- «Накопленное знание — не контекст разговора» должно быть правилом политики, а не побочным эффектом формы одного инструмента.
- Локальной рабочей памяти не нужен конкретный инструмент: `docs/local/**` — сначала файлы, индексируемые при наличии Basic Memory.
- Переименованные managed-шаблоны иначе оставляли бы устаревшие копии навсегда; retire — забота sync, а не документальная заметка.

## Alternatives Considered

### Оставить ConPort опциональной фичей

Отвергнуто. Стандарты продолжали бы описывать backend, который никто не поддерживает; семантике нужно инструментально-независимое место; каждая интеграция несла формулировки адаптера.

### Механически переименовать формулировки ConPort в Basic Memory

Отвергнуто. Это стёрло бы различие между retrieval-слоем (Basic Memory) и таксономией/семантикой памяти (project memory) и воссоздало связность с другим именем инструмента.

### Положить таксономию внутрь `basic-memory`

Отвергнуто. Проекты без Basic Memory потеряли бы правила локальной памяти; возможность зависела бы от одной реализации, что противоречит вводимому разделению capability/implementation.

### Выпустить удаление отдельным релизом до появления замены

Отвергнуто. Промежуточный релиз без `conport` и без `retrieval-routing` ломает downstream-манифесты (`SyncError` на неизвестной фиче) без цели для миграции.

## Consequences

### Benefits

- Стандарты описывают семантику памяти, а не конкретный заброшенный backend.
- Локальная межсессионная память получает стандартный, игнорируемый git'ом дом с фиксированной таксономией и явным путём продвижения; каноническая документация защищена от дампов сессионного состояния.
- Retrieval становится решением о маршрутизации с обязанностями доказательства и верификации, а не инструментальной привычкой.
- Переименованные и отозванные managed-шаблоны убирают за собой.

### Costs Or Tradeoffs

- Каждый downstream-манифест с `conport` ломается на первом рендере после апгрейда до миграции; процедуру миграции несёт скилл `update-ai-standards`.
- `doctor` обязан различать зону локальной памяти и канонические зоны (ослабленный аудит) — усложнение аудита.
- Две новые фичи и одна экспериментальная capability увеличивают реестр и граф фич.

## Verification

- `uv run python scripts/ai_sync.py render/check --project-root .`, `uv run ruff check`, `uv run mypy`, `uv run python -m pytest` — зелёные на каждой фазе.
- `rg -i conport` по репозиторию находит только датированную историю (`docs/decisions/**`, `docs/tasks/**`, `docs/archive/**`, `CHANGELOG.md`) плюс намеренные ссылки инструкции миграции в шаблонах `update-ai-standards` и `deploy-ai-retrieval-stack`.
- Policy-тесты утверждают, что сгенерированный `AGENTS.md` не содержит раздела ConPort; тесты retire-механизма покрывают удаление managed-копий и выживание пользовательских файлов.
- Поведенческие сценарии A–E из issue #16 на этом репозитории как референсной конфигурации при закрытии итерации.

## Observations

- [decision] ConPort удалён; его семантика живёт в инструментально-независимых правилах `project-memory`.
- [decision] `retrieval-routing` — связующий policy-слой; capability (project-memory, semantic code, structural code) именуются независимо от реализаций (Basic Memory, Chroma, graph-инструменты).
- [decision] Локальная рабочая память в `docs/local/**` никогда не канонична; продвижение в каноническую документацию — явная операция.
- [fact] `sync-templates` прежде никогда не удалял файлы назначения, поэтому переименованные шаблоны оседали бы; retire защищён маркером и не трогает переписанные пользователем файлы.
