# РЕШЕНИЕ: standards-install-and-cold-start

Английский источник истины: [2026-08-29-standards-install-and-cold-start.md](2026-08-29-standards-install-and-cold-start.md)

## Статус

Принято

## Дата

2026-08-29

## Контекст

Скилл обновления из 2.2.0 работает только там, где уже развёрнут, что оставляет два сценария неопределёнными: установка ai-standards в проект без какого-либо развёртывания и обновление развёртывания старше самого скилла (проблема курицы и яйца при бутстрапе). Сопровождающий хочет, чтобы оба сценария обслуживались короткими промптами пользователя — URL для установки, голая фраза для обновления, — при которых агент обследует проект, анонсирует новые фичи и включает только подтверждённое.

Три факта ограничивают форму. Во-первых, агент, получивший только URL репозитория, начнёт импровизировать установку, если промпт не привяжет его к собственной процедуре стандарта. Во-вторых, дайджест, анонсирующий фичи только по `since`, даёт ложноположительные срабатывания для проектов, уже включивших их при актуальном контенте, но со старым пином — наблюдалось вживую на cockpit (пин 2.1.0, контент 2.2.0, две фичи уже включены). В-третьих, репозиторий стандартов должен присутствовать локально для `render`/`sync-templates` в любом сценарии, так что получение исходника — шаг каждого режима, а не особый случай.

## Решение

Скилл `update-ai-standards` становится двухрежимным; имя и активаторы сохраняются. **Install mode** добывает исходник, обследует проект (существующий `AGENTS.md` и его происхождение, стеки, раскладку и язык документации, наличие ConPort/Basic Memory, CI, трекер, агентские окружения), предлагает набор фич по одной строке с рекомендациями и разворачивает подтверждённый набор через `init-project`, заполненный манифест, `render`, `sync-templates`, `check` и `doctor`. **Upgrade mode** сохраняет процедуру 2.2.0 с двумя уточнениями: дайджест анонсирует только фичи, которые новые **и ещё не включены** (отсутствуют в списке `features` манифеста), а бутстрап-преамбула выполняет `render` + `sync-templates` до дайджеста, когда развёрнутый скилл отсутствует или старше файла.

Файл скилла написан так, чтобы выполняться прямо из чекаута: холодный старт в шапке сообщает, что файл и есть процедура, когда в целевом проекте нет развёртывания. Канонические промпты пользователя опубликованы в README («Standard Install And Update Prompts») и в release notes 2.2.1 дословно; установка записывает `standards_source` в метаданные манифеста, поэтому промпты обновления после этого в URL не нуждаются.

## Обоснование

- файл скилла — единственный артефакт, гарантированно присутствующий в каждом сценарии: чекаут существует по определению в случаях установки и бутстрапа, развёрнутая копия — в установившемся режиме, — поэтому один самодостаточный файл обслуживает всё без второго канала распространения
- привязка промпта к файлу процедуры превращает URL в установку *именно этого* стандарта, а не импровизацию; контракт — файл процедуры, а не URL
- исключение уже включённых фич из дайджеста делает анонс правдивым, от чего зависит весь шаг подтверждения
- запись `standards_source` при установке позволяет последующим промптам быть короткими; расположение источника — знание о развёртывании, значит место ему в манифесте развёртывания, и в шапку `AGENTS.md` он попадает бесплатно

## Рассмотренные альтернативы

### Отдельный скилл `install-ai-standards`

Отклонено. У проекта без развёртывания нет канала развёртывания, поэтому скилл установки мог бы выполняться только из чекаута репозитория — то же свойство холодного старта, которое уже даёт двухрежимный файл. Два скилла дублировали бы бутстрап-логику и добавляли бы два пути к файлам в канонические промпты.

### Считать голый URL достаточным промптом установки

Отклонено как каноническая форма. URL доставляет код; без указания процедуры агент импровизирует. README репозитория маршрутизирует агентов на файл скилла, поэтому промпт с одним URL обычно срабатывает, но в release notes публикуется детерминированная форма, называющая файл.

### Анонсировать по `since` вне зависимости от манифеста

Отклонено. Это даёт ложноположительные для развёртываний, чей контент актуален, а пин устарел, — ровно ту ситуацию дрейфа, которую этот цикл релиза ужесточал и в других местах.

## Последствия

### Польза

- оба сценария сопровождающего работают от одного короткого промпта, опубликованного дословно в release notes и README
- дайджест правдив: уже включённое не анонсируется повторно, включение без подтверждения невозможно
- последующие промпты обновления не нуждаются в URL, потому что развёртывание несёт собственный указатель на источник

### Компромиссы

- файл скилла стал длиннее и несёт маршрутизацию режимов; развёрнутая копия стоит нескольких лишних строк в каждом агентском окружении
- `standards_source` — конвенция, а не принуждение: развёртывания, установленные до 2.2.1, не имеют его, пока обновление не запишет

### Дальнейшие шаги

- опубликовать три канонических промпта дословно в release notes 2.2.1
- скилл в развёртываниях 2.2.0 обретает осведомлённость о включённом только после первого обновления до 2.2.1; до тех пор бутстрап-промпты называют проверку манифеста явно

## Observations

- [decision] Скилл обновления двухрежимный (Install/Upgrade) и самодостаточен из чекаута; отдельного скилла установки не существует.
- [decision] Дайджест обновления анонсирует только фичи, которые новые и отсутствуют в списке `features` манифеста.
- [fact] Установка записывает `standards_source` в метаданные манифеста, а метаданные манифеста рендерятся в шапку `AGENTS.md`.
- [fact] Канонические промпты опубликованы дословно в README и в release notes 2.2.1.
