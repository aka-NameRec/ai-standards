# РЕШЕНИЕ: local-memory-date-prefix-naming

Английская версия: [2026-10-11-local-memory-date-prefix-naming.md](2026-10-11-local-memory-date-prefix-naming.md)

## Статус

Принято

## Дата

2026-10-11

## Контекст

Пользовательское issue #23 описало реальный кейс devcats (2026-10-11):
параллельные агентские сессии за один день создали локальные заметки в
`docs/local/**` в трёх конкурирующих конвенциях имён — таймстамп-префиксы
(`20261011-170555-…`), таймстамп плюс тема, тема без даты или тема с
суффиксом-датой, — тогда как канонические датированные артефакты того же
дерева всегда именуются `YYYY-MM-DD-<topic-slug>.md`. Локальная рабочая
память просматривается, сортируется и линкуется рядом с каноническими
`docs/decisions/**`, поэтому разнобой нотаций ломает сортировку по дате,
добавляет синтаксический шум и порождает споры сессий о «правильной»
конвенции. Путь переноса усугубляет проблему: локальную заметку при переносе
в каноническую документацию приходилось переименовывать, ломая человеческое
узнавание файла.

Два действующих правила явно освобождали локальную область от датированных
имён и потому конфликтовали с правилом-кандидатом (заявленное в issue
«отсутствие конфликта» не подтвердилось): формулировка Note Shape во фрагменте
`project-memory` («dated file names … do not apply inside the local memory
area») и формулировка Note Shape во фрагменте `basic-memory` («living
documents and working memory do not»).

## Решение

1. Принимается единый стандарт именования локальной памяти: каждый
   Markdown-документ, который агент создаёт в этой области, именуется
   `YYYY-MM-DD-<topic>.md` — ровно в нотации канонических датированных
   артефактов. Дата — дата создания заметки; правки содержимого не
   переименовывают заметку; слияние при гигиене сохраняет старшую дату.
2. Целевая функция — путь переноса: локальная заметка, чьё имя уже следует
   канонической нотации, переносится в каноническую документацию под тем же
   именем файла, а совпадения имён между областями остаются редкими.
3. Оба конфликтующих места сужаются в том же наборе изменений, а не обходятся:
   требования к *телу* канонической заметки (`## Observations`, `## Relations`,
   форма frontmatter) по-прежнему не применяются в локальной области, но
   дата-префикс имени файла теперь обязателен.
4. `ai-sync doctor` сообщает `local-note-without-date-prefix` — WARNING, без
   авторемонта (модульный контракт ai-sync запрещает переименование заметок в
   `--fix`). Существующие неконформные заметки мигрируют оппортунистически во
   время гигиены рабочей памяти; массовая миграция не предписывается.
5. Правило прослеживается как `PM-001` в `rule_map.toml` с контрактом
   поведенческого сценария
   `docs/scenarios/PM-001-local-note-date-prefix.md` (исполнение —
   `ai-standards-evals`, issue #18).

## Почему так

- Единая нотация с каноническими датированными артефактами снимает спор о
  конвенции конструктивно, вместо арбитража между тремя конвенциями.
- Сохранение имени файла при переносе удерживает стабильным человеческое
  опознание заметки — именно за это заплатил кейс devcats.
- Исполнение «только отчёт» держит старые деревья зелёными в CI, пока
  агентское правило блокирует поведение в месте его возникновения.

## Рассмотренные альтернативы

### Сохранить исключение, стандартизировать только локальными правилами проектов

Отклонено: проекту cockpit уже пришлось добавить локальное правило, чтобы
зафиксировать одну нотацию, — ровно то дублирование на каждый workspace,
которое стандарты существуют предотвратить.

### Нотация с таймстамп-префиксом (`YYYYMMDD-HHMMSS-`)

Отклонено: она сортируется по имени раньше канонической нотации только внутри
своего стиля префикса, несёт шумные разряды, которые человек не читает, и всё
равно отличается от нотации канонических артефактов, так что перенос продолжил
бы переименовывать файлы.

### Массовая миграция существующих неконформных заметок

Отклонено как предписание: локальная память — агентское рабочее состояние,
переименования перегенерируют пермалинки Basic Memory, и ценность переименования
старой заметки редко окупает шум. Doctor сообщает о нарушениях; гигиена
переименовывает их оппортунистически.

## Последствия

### Польза

- Единая нотация имён для локальных и канонических датированных артефактов;
  перенос сохраняет имена файлов.
- Три формы валидации правила: детерминированная статическая проверка (regex
  имени), предупреждение doctor и поведенческий сценарий.
- Старые деревья проходят CI: нарушение — предупреждение.

### Компромиссы

- Принуждение для существующих заметок носит рекомендательный характер; дерево,
  игнорирующее отчёт, сохраняет смешанные имена.
- Заметки, легитимно созданные до правила, хранят неконформные имена, пока их
  не коснётся гигиена.

## Наблюдения

- [decision] Файлы локальной памяти следуют канонической нотации
  `YYYY-MM-DD-<topic>.md`, чтобы перенос в каноническую документацию сохранял
  имя файла; дата — дата создания заметки.
- [decision] Doctor сообщает `local-note-without-date-prefix` как предупреждение
  без авторемонта; переименование остаётся вне `--fix` по модульному контракту
  ai-sync.
- [fact] Две действующие формулировки (Note Shape в `project-memory`, Note Shape
  в `basic-memory`) явно освобождали локальную память от датированных имён и
  потребовали сужения — заявленное в issue «отсутствие конфликта» не
  подтвердилось.
