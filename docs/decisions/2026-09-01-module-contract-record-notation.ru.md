# РЕШЕНИЕ: module-contract-record-notation

Английский источник истины: [2026-09-01-module-contract-record-notation.md](2026-09-01-module-contract-record-notation.md)

## Статус

Принято

## Дата

2026-09-01

## Контекст

Обращение пользователя #10 зафиксировало одно и то же проявление в двух разных проектах: агент, попросенный создать модульный контракт, писал корневой `MODULE_CONTRACT.md` вместо записи в `docs/architecture/**` и без frontmatter `title`, который требует индексационный слой Basic Memory. Правила называли ровно один артефакт — «Create MODULE_CONTRACT.md only for major, risky, shared, or architecturally non-obvious modules» — и ни разу не называли место хранения и нотацию записи, поэтому побеждало литеральное прочтение, а паттерн повторялся от проекта к проекту. Корневой файл стоял и первым в списке канонических источников discovery gate, и в перечнях канонической документации, закрепляясь как целевой формат.

Слой знаний уже ждёт записи, а не корневые файлы: заметки идентифицируются frontmatter `title`, датированные артефакты следуют нотации `YYYY-MM-DD-<topic-slug>.md`, а `docs/architecture/**` — устоявшийся канонический дом, общий с архитектурными decision records. Настоящее решение фиксирует, где живёт модульный контракт и как он выглядит.

## Решение

Модульный контракт — одна запись в `docs/architecture/**`:

- файл называется `YYYY-MM-DD-module-contract-<module-slug>.md` — нотация decision records с явной меткой `module-contract` в slug, чтобы список каталога показывал контракты с первого взгляда;
- frontmatter несёт `title` (идентификатор для Basic Memory) и `type: module-contract` (маркер классификации);
- одна запись — один контракт: ownership, non-goals, inputs, outputs, dependencies, invariants, failure boundaries, verification;
- контракты по-прежнему создаются только для крупных, рискованных, разделяемых или архитектурно неочевидных модулей;
- корневой `MODULE_CONTRACT.md` — legacy-форма: discovery и ревью по-прежнему распознают и читают его, но ни одно правило не создаёт новые, а `ai-sync doctor` сообщает о legacy-размещении предупреждением.

Маркер классификации — поле frontmatter `type: module-contract`, а не имя файла. Decision records о контрактах тоже законно несут `module-contract` в slug (пример — `2026-08-28-module-contract-gate-feature-placement.md`, решение, а не контракт), поэтому glob по имени — лишь дешёвая подсказка; маркер во frontmatter точен и подключается к schema-инструментарию фичи Basic Memory.

## Почему

- Отказ был системным: формулировки, а не поведение отдельных агентов, порождали корневой файл в двух проектах, значит чинить нужно формулировки.
- Запись в `docs/architecture/**` кладёт контракт туда, где discovery gate уже сканирует и где работает индексация Basic Memory, — прежний корневой файл был невидим для заметочных конвенций.
- Метка в slug плюс тип во frontmatter дают и дешёвый поиск (glob по имени, grep по содержимому), и точную классификацию, не опираясь только на один из механизмов.

## Рассмотренные альтернативы

### Отдельный каталог `docs/contracts/**`

Отклонено: дробит канонические места, противоречит общему правилу именования, которое уже покрывает `docs/architecture/**`, и вынуждало бы discovery gate и ревью-проверки сканировать третье место.

### Оставить корневой `MODULE_CONTRACT.md` целевым форматом

Отклонено: это и есть проявление из issue #10; файл вне заметочных конвенций — без frontmatter-идентичности, без датированной нотации, невидим для инструментария записей.

### Метить контракты только тегами

Отклонено как единственный маркер: теги — для сквозных тем; тип заметки подключает команды `infer`/`validate`/`diff` и даёт discovery точный предикат. Метку в slug уже покрывает дешёвую человекочитаемую подсказку.

## Последствия

### Польза

- записи контрактов — полноценные заметки: с заголовком, датой, в индексе, находятся grep-ом;
- инструкции discovery, ревью и capture-knowledge согласованы об одном месте и одной нотации;
- legacy-файлы продолжают работать — распознавание остаётся, создание прекращается, doctor подталкивает к миграции.

### Компромиссы

- существующие корневые `MODULE_CONTRACT.md` в downstream-проектах остаются до миграции; doctor сообщает о них вместо автоматического переноса, потому что перенос заметки — переименование, а переименования требуют решения.

### Продолжения

- собственный контракт этого репозитория перенесён в том же наборе изменений: `docs/architecture/2026-09-01-module-contract-ai-sync.md` (ранее `docs/MODULE_CONTRACT.md`, впервые записан 2026-08-27).

## Observations

- [decision] Модульный контракт живёт одной записью `YYYY-MM-DD-module-contract-<module-slug>.md` в `docs/architecture/**` с frontmatter `title` и `type: module-contract`.

- [fact] Один только glob по имени `module-contract` неверно классифицирует decision records о контрактах; точный маркер — тип во frontmatter.
