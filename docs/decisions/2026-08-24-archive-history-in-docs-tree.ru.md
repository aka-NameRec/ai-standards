# РЕШЕНИЕ: archive-history-in-docs-tree

English version: [2026-08-24-archive-history-in-docs-tree.md](2026-08-24-archive-history-in-docs-tree.md)

## Status

Accepted

Определяет переработку pull request #7 (ветка knowledge tree), который не сливается в исходном виде.

## Date

2026-08-24

## Context

Экспорты чатов (`*-log-*.md`) — первичные источники: они фиксируют, как решения принимались на самом деле, и их потеря теряет рассуждения, стоящие за записанным результатом. Pull request #7 перенёс двенадцать таких файлов из дерева знаний в `temp/`, что дважды искажает их ценность: имя объявляет «временными» файлы, являющиеся историей, а в соседнем репозитории `cockpit` каталог `temp/` — игнорируемая git-ом рабочая зона, то есть одно имя означало бы противоположное в пределах одного воркспейса.

Поиск тянет в две стороны. Текущая работа не должна выдавать полмегабайта транскриптов на каждый запрос, но явное «изучи историю» обязано их находить. Basic Memory не умеет выражать первую половину: его фильтры поиска (`--tag`, `--type`, `--meta`, `--status`) только включающие, поэтому архивный материал нельзя ни понизить, ни исключить на момент запроса. Зарегистрировать архив как второй проект Basic Memory внутри дерева тоже невозможно: индексатор запрещает пересекающиеся деревья каталогов.

Человек отделяет документацию от кода, поэтому архив принадлежит документационному дереву, а не корню репозитория рядом с ним.

## Decision

1. Исторические экспорты чатов живут в `docs/archive/**` — внутри дерева знаний, под версионным контролем.
2. Basic Memory исключает это поддерево паттерном `archive/` в `.bmignore`. Форма «имя каталога» принципиальна: `archive/*` ничего не исключает, потому что при рекурсивном обходе матчер видит сам подкаталог, и корневые паттерны перестают сопоставляться. Запись в игнорируемые пути отвергается sync API, поэтому агент не может создать заметку в архиве через инструменты, доступные модели.
3. Chroma индексирует `docs/archive` отдельной коллекцией (например `<project>-history`) по прецеденту мульти-коллекций воркспейса devcats. Кодовые коллекции обязаны объявлять явные корни, не накрывающие `docs/archive`: корень `"."` примешал бы историю в кодовый индекс.
4. Второй проект Basic Memory не создаётся, реестр и адаптер cockpit не меняются; более ранний кандидат — проект-сиблинг `<name>-archive` — отклонён.
5. `ai-sync doctor` пропускает `docs/archive` при аудите заметок и проверяет, что активный `.bmignore` действительно несёт исключение `archive/`. Граница — одна конвенционная строка в конфигурационном файле, а не структурное свойство инструмента, поэтому ей нужна детерминированная проверка: потерянная строка иначе молча выльет транскрипты обратно в граф.
6. Правило именования `-log-` становится `docs/**/*-log-*.md` — текущий глоб `docs/*-log-*.md` не пересекает границы каталогов — и называет `docs/archive/**` домом экспортов чатов.

## Why

- транскрипты — поисковый корпус, а не участник графа: у них нет осмысленной структуры сущностей и связей, поэтому Basic Memory им ничего не даёт, а включающие фильтры не удерживают их вне повседневной выдачи
- именованные коллекции Chroma уже моделируют «ищется только по явной просьбе»; история становится ещё одной коллекцией, а не новой сущностью инструмента
- один дом документации совпадает с тем, как человек читает репозиторий: код здесь, всё написанное для людей — под `docs/`
- архив остаётся в git, поэтому ничего не зависит от выживания какого-либо индекса

## Alternatives Considered

### Оставить экспорты чатов в `temp/` (pull request #7 в исходном виде)

Отклонено. Имя искажает ценность файлов и сталкивается с противоположным значением `temp/` в cockpit.

### Каталог `archive/` в корне, зарегистрированный как отдельный проект Basic Memory

Отклонено. Индексатор запрещает пересекающиеся деревья, архив выпал бы из человеческого вида документации, а cockpit потребовал бы нового поля реестра, логики адаптера и ещё одной проектной сущности на репозиторий.

### Пессимизировать архивный материал внутри общего индекса Basic Memory

Отклонено как невозможное: у Basic Memory нет исключающих фильтров запроса, поэтому архив можно только структурно исключить, но не понизить.

### Хранить историю только в Chroma, вне git

Отклонено. Экспорты чатов — история проекта; git — место, где проект хранит историю.

## Consequences

### Benefits

- повседневный поиск остаётся чистым, а явное исследование истории работает прицельным запросом в коллекцию
- разделение ролей единообразно: код и исторические корпуса — в Chroma, живой граф знаний — в Basic Memory, полная история — в git
- новых сущностей нет: одна строка `.bmignore` на машину, одно объявление коллекции на проект

### Costs Or Tradeoffs

- `.bmignore` разрешается на уровне машины, и `archive/` исключает каждый каталог с таким именем в каждом проекте Basic Memory. При единой конвенции «docs/archive = история» это и задумано; `doctor` обязан показать расхождение, когда проект действительно хочет индексировать свой `archive/`.
- вики-ссылки из decision record-ов в архив не резолвятся в графе Basic Memory; используйте относительные Markdown-ссылки — они работают в git и при чтении, ценой проходимости графа.
- семантический поиск по истории требует объявления и индексации коллекции Chroma в каждом проекте; без неё архив остаётся доступным grep-у, но не семантическому поиску.

## Verification

- На изолированной конфигурации Basic Memory (`BASIC_MEMORY_CONFIG_DIR`) паттерн `archive/` не пропускает архивную заметку в базу, пока соседняя живая заметка индексируется; паттерн `archive/*` её не исключает.
- Запись в игнорируемые пути отвергается сообщением "matches Basic Memory ignore rules".
- Вложенный проект Basic Memory отвергается сообщением "Projects cannot share directory trees", что исключает архив-проект внутри дерева.
- Конфигурация «коллекция на корень» проверена по воркспейсу devcats (`devcats-broadleaf-code`, `devcats-mkt-backend-code`, …) и шаблону `code-index.toml`, поставляемому с фичей chroma.

## Observations

- [decision] Исторические экспорты чатов живут в `docs/archive/**` — внутри дерева знаний, под версионным контролем.
- [decision] Basic Memory исключает поддерево архива паттерном `archive/` в `.bmignore`; форма `archive/*` не исключает ничего, потому что при рекурсивном обходе матчер видит сам подкаталог.
- [decision] Chroma индексирует `docs/archive` отдельной коллекцией, а кодовые коллекции объявляют явные корни, его не накрывающие.
- [tradeoff] `.bmignore` разрешается на уровне машины и исключает каждый каталог с именем `archive` в каждом проекте Basic Memory, поэтому `doctor` обязан показать расхождение, когда проект действительно хочет индексировать свой `archive/`.
- [tradeoff] Вики-ссылки в архив не резолвятся в графе Basic Memory; документы используют относительные Markdown-ссылки, ценой проходимости графа.
