# РЕШЕНИЕ: разделение ролей хранилищ знаний

Английская версия: [2026-08-24-knowledge-store-role-separation.md](2026-08-24-knowledge-store-role-separation.md)

## Status

Accepted

Спутник решения [2026-08-24-archive-history-in-docs-tree.ru.md](2026-08-24-archive-history-in-docs-tree.ru.md), применяющего это разделение к историческим экспортам чатов.

## Date

2026-08-24

## Context

Basic Memory и Chroma выглядят функционально близкими: один индексирует документацию, другой — код, а воркспейс devcats уже делит одну базу Chroma на коллекции по областям (`devcats-broadleaf-code`, `devcats-mkt-backend-code`, …). Возник вопрос: не является ли Basic Memory лишней сущностью, которую можно свернуть в Chroma, разместив документацию и истории как дополнительные коллекции.

Проверка установленной инсталляции изменила картину:

- Basic Memory в этом воркспейсе работает с `embedder = None` — векторной работы он не выполняет вовсе, поэтому инструменты даже не конкурируют за одну модальность поиска.
- Уникальная ценность Basic Memory — граф: сущности, наблюдения, связи, вики-ссылки, обход `build-context`, адресация пермалинками — плюс готовый MCP-инструментарий записи и правки заметок.
- Фильтры поиска Basic Memory (`--tag`, `--type`, `--meta`, `--status`) только включающие; способа понизить или исключить класс материала на момент запроса нет.
- `where`-фильтры Chroma поддерживают исключение (`$ne`), а именованные коллекции уже моделируют «ищется только по явной просьбе».

## Decision

Три хранилища сохраняют различные роли; Basic Memory не сливается с Chroma.

- **Chroma** — векторный поиск по коду и историческим корпусам (экспортам чатов) именованными коллекциями; история запрашивается только прицельным обращением к коллекции.
- **Basic Memory** — граф живого дерева знаний (`docs/**` без архива), идентификация заметок по `title` во frontmatter, адресация пермалинками.
- **ConPort** — операционная память: активный контекст, прогресс, передача сессий; транзиентная, никогда не каноническая.
- **git** — каноническая истина всего; каждый индекс — проекция, которую можно пересобрать.

Правило фрагмента chroma «хранилища никогда не смешиваются» трактуется на уровне гранулярности коллекции/индекса: Chroma может держать несколько именованных коллекций с разными ролями, но ни одно хранилище не делит один индекс или коллекцию с другим.

## Why

- граф не эмулируется фильтрами: «какие решения реализуют это доменное правило» — обход, а не запрос ближайших соседей
- сворачивание правки заметок в Chroma означало бы написание Markdown-индексатора и MCP-инструментария, которые Basic Memory уже поставляет
- при `embedder = None` консолидация не удалила бы никакой дублирующейся работы — только возможности

## Alternatives Considered

### Полностью заменить Basic Memory на Chroma

Отклонено. Теряются обход графа, адресация `memory://` и MCP-инструменты правки заметок; самодельный чанкер Markdown нужен лишь ради ничего.

### Одно хранилище Basic Memory на всё, включая транскрипты

Отклонено. У транскриптов нет структуры сущностей и связей, граф им ничего не даёт, а включающие фильтры не удерживают их вне повседневной выдачи.

### Хранить историю только в Chroma, вне git

Отклонено. Экспорты чатов — история проекта, а git — место, где проект хранит историю.

## Consequences

### Benefits

- единая формула ролей: код и исторические корпуса — в Chroma, живой граф — в Basic Memory, операционное состояние — в ConPort, канонические файлы — в git
- дизайн архива ([2026-08-24-archive-history-in-docs-tree.ru.md](2026-08-24-archive-history-in-docs-tree.ru.md)) вытекает из неё напрямую

### Costs Or Tradeoffs

- два индексатора на поддержке вместо одного
- семантический поиск по истории требует объявления коллекции в `code-index.toml` каждого проекта; без неё архив доступен grep-у, но не семантическому поиску

## Verification

- `embedder = None`, только включающие фильтры и отказ вкладывать проекты («Projects cannot share directory trees») проверены на установленном Basic Memory.
- Конфигурация мульти-коллекций проверена по воркспейсу devcats и шаблону `code-index.toml`, поставляемому с фичей chroma.

## Observations

- [decision] Basic Memory не сливается с Chroma; хранилища сохраняют различные роли на уровне гранулярности коллекции/индекса.
- [decision] Chroma держит код и исторические корпуса именованными коллекциями; Basic Memory — живой граф знаний; ConPort остаётся операционным; git — каноническим.
- [fact] Basic Memory в этом воркспейсе работает с `embedder = None`, поэтому дублирования векторной работы между хранилищами нет.
