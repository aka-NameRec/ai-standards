# DECISION: non-note-data-file-doctor-policy

English original: [2026-09-03-non-note-data-file-doctor-policy.md](2026-09-03-non-note-data-file-doctor-policy.md)

## Status

Принято

## Date

2026-09-03

## Context

Пользовательский issue #13 описал кейс devcats: 37 фантомных сущностей (PNG-скриншоты, выгрузки CSV, сырые логи, PDF) в `docs/artifacts/**` индексируемого дерева знаний, и одна выгрузка чата на 152K, стоившая 276 чанков и ~88 секунд процессорного времени на построение embeddings при каждом reindex. Issue предлагал подход «только маски»; последующая сессия (задачи `0tkrogf`–`0tkrpc0`) разобрала альтернативы, прежде чем политика была зафиксирована.

Факты, проверенные по исходникам Basic Memory 0.23.2, определили пространство решений:

- обновления индекса стартуют из трёх точек, которые ai-standards не контролирует: file watcher MCP-сервера (автозапуск в lifespan сервера), CLI (`bm reindex`, `bm sync`) и API-роутеры, — значит, перехватить индексацию на входе со стороны ai-standards невозможно;
- Basic Memory уже учитывает маски — watcher и обход reindex применяют глобальный `~/.basic-memory/.bmignore` и проектный `.gitignore` в корне проекта индексатора, — то есть механизм fail-closed существует и требует лишь корректных масок;
- в синтаксисе масок нет отрицания `!`, поэтому «белый список» вида «только Markdown» невыразим, а полный список бинарных форматов принципиально нельзя составить — но он и не нужен.

## Decision

1. `ai-sync doctor` сообщает находку `non-note-data-file-inside-knowledge-tree` — WARNING, без автопочинки — для любого не-Markdown, не-скрытого, незамаскированного файла под деревом знаний. Объявленные overrides и поддерево `archive/` исключены, чтобы не дублировать другие находки.
2. Матчер проверки повторяет семантику масок самого индексатора (`.gitignore` в корне дерева знаний плюс глобальный `.bmignore` рядом с конфигурацией индексатора, читаемый при открытом feature-гейте). Уже замаскированное дерево остаётся тихим: любой мусор либо замаскирован (не индексируется), либо замечен — множество детекции замкнуто без перечисления форматов.
3. Severity остаётся WARNING. Намерение «это не индексировать» обслуживает блокирующее правило на стороне агента — бюллетень фрагмента `basic-memory`, Reindexing Policy в usage-гуиде и скилл `audit-knowledge-tree` говорят одно: реиндексируйте только после чистого отчёта `ai-sync doctor`.
4. Поддержка отрицания `!` в масках Basic Memory — вне области. Принятый подход от неё не зависит; локальный порт матчера придётся синхронизировать, если семантика upstream изменится.

## Why

- Формат-агностичный детектор («всё, что не заметка») заменяет невозможное перечисление бинарных форматов; маски должны покрывать только форматы, которые проект реально хранит.
- Отказаться от индексации может только сам индексатор, и он уже отказывается для замаскированных путей, — задача doctor гарантировать корректность масок, а не переизобретать отказ.
- Warning плюс явное правило для агента дают блокировку там, где она работает (потоки с участием агента), не окрашивая doctor в красный для каждого legacy-дерева.

## Alternatives Considered

### ERROR severity (гейт по exit-коду)

Отклонено: `doctor` завершается ненулевым кодом на ошибках и по контракту пригоден для CI, поэтому каждое legacy-дерево с мусором упало бы в CI сразу после обновления стандартов — включая проекты, где feature `basic-memory` никогда не включалась. Блокирующее правило доставляет то же намерение туда, где оно нужно, без этой поломки.

### Блокировать индексацию на входе (обёртка над `bm` или перехват watcher)

Отклонено как нереализуемое: watcher автозапускается в lifespan MCP-сервера, пути CLI и API вызываются напрямую. Обёртка над `bm` не покрыла бы watcher и MCP-инструменты.

### Сначала upstream-PR с отрицанием `!`, потом строить на белых списках

Отложено: реалистично (сам матчер — небольшая правка; дефолтный `.bmignore` уже обещает «standard gitignore-style syntax»), но в целом средняя сложность — трудность в семантике prune обходчиков для ре-включения под исключёнными каталогами, а приём мейнтейнерами не гарантирован. Принятый подход работает и без него.

### Направлять файлы данных в `docs/archive`

Исправлено, а не принято: индексатор обходит `docs/archive`, пока строка `.bmignore` (`archive/`) не исключит каталог, и по конвенции архив хранит вербатим-источники, а не файлы данных. Данные лежат вне дерева либо замаскированы на месте, пока на них ссылаются заметки.

## Consequences

### Benefits

- замкнутая детекция: любой не-заметочный файл в дереве либо замаскирован, либо замечен;
- контракт модуля ai-sync не изменился — только отчёт, read-only конфигурация индексатора, `--fix` не расширен;
- legacy-деревья продолжают проходить CI.

### Trade-offs

- принуждение носит рекомендательный характер: человек, игнорирующий отчёт, всё равно может запустить reindex;
- локальный матчер сознательно дублирует семантику upstream и требует синхронизации при её изменении.

## Observations

- [decision] Doctor сообщает о файлах данных в дереве знаний находками `non-note-data-file-inside-knowledge-tree` с матчером, повторяющим семантику масок индексатора, поэтому уже замаскированное дерево остаётся тихим.
- [decision] Severity — WARNING с блокирующим правилом на стороне агента; гейт ERROR по exit-коду отклонён, потому что legacy-деревья без включённого feature индексатора падали бы в CI.
- [fact] Basic Memory запускает обновления индекса из трёх неконтролируемых точек — file watcher MCP-сервера, CLI и API-роутеры, — поэтому перехватить индексацию на входе со стороны ai-standards невозможно.
- [fact] Списку масок не нужно перечислять форматы: детектор «не-Markdown» не зависит от формата, а маски покрывают только форматы, которые проект реально хранит.
