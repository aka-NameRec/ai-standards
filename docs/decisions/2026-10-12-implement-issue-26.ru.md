# РЕШЕНИЕ: реализация issue 26

Локализованная версия: [2026-10-12-implement-issue-26.md](2026-10-12-implement-issue-26.md)

## Статус

Принято

## Дата

2026-10-12

## Контекст

Issue #26 (верифицированный отзыв о 2.8.1, архив —
`docs/archive/2026-10-12-ai-standards-2.8.1-defects.md`, задачная запись
`docs/tasks/26-verified-user-feedback-2-8-1.md`) подтверждает шесть
дефектов: процедура код-ревью разворачивается только для kilo; пункт
`autonomous-task-run` о коммитах противоречит `capture-knowledge`; шаг
фиксации знаний автономного запуска игнорирует фичи проекта и захардкоженный
`docs/tasks/`; форма ветки зафиксирована в навыке вместо правил проекта;
фрагмент `basic-memory` по-прежнему снимает с `docs/local/**` все правила
канонических заметок и содержит висячую ссылку на раздел; `update-ai-standards`
молча разворачивает новые навыки, привязанные к уже включённым фичам, до
шага анонса. Шесть направлений (D1–D6) приняты пользователем 2026-10-12.

## Решение

1. **D1 — общий справочник процедуры.** Процедура по проходам переезжает в
   новый инфраструктурный шаблон, разворачиваемый как
   `.ai-standards/references/standard-code-review-procedure.md` (gated на
   фичу `code-review`; паттерн M4/M5). Все четыре варианта
   `standard-code-review` ссылаются на общий путь; частный
   `references/procedure.md` kilo-навыка упраздняется; указатели во
   фрагменте обновляются. Критерий: после `ai-sync sync-templates` в проекте
   с `tooling.agents = ["codex", "claude", "cursor", "kilo"]` каждая
   развёрнутая копия `standard-code-review` ссылается на существующий файл,
   а список «Safe to fix without asking» доступен каждому агенту.
2. **D2 — согласование согласия на коммиты.** Оговорка о старшинстве (п. 3
   решения о принятии `autonomous-task-run`) выносится в оба места: в пункт
   «Never» навыка `capture-knowledge` добавляется исключение для
   автономного запуска (коммиты под стоящим согласием запуска; отправка
   всегда явная), а в `core/git-workflow` появляется явная строка
   исключения. Критерий: оба текста называют исключение, и ни одна
   формулировка не ослабляет правило отправки.
3. **D3 — фиксация знаний по включённым фичам.** Шаг 7 `autonomous-task-run`
   и условие завершения требуют только те части, которые определены
   включёнными фичами проекта; пропущенные части фиксируются в completion
   report; в entry gate добавляется знание включённых целей фиксации. Каталог
   задачных записей становится настраиваемым ключом
   `[knowledge_capture] tasks_tree` (по умолчанию `tasks`) — документируется
   в шаблоне манифеста и упоминается во фрагменте и навыке (по образцу
   `[project_memory] local_tree`); ai-sync ключ пока не потребляет.
   Критерий: в проекте без `knowledge-capture`/`project-memory` шаг 7
   исполним, пропуски отражаются в отчёте, ключ описан в шаблоне манифеста.
4. **D4 — имя ветки по правилам проекта.** Шаг 1 обращается к правилам
   проекта, `<purpose>/<task_id>-<slug>` — общее значение по умолчанию
   (зеркало формулировки шага 6 о коммитах). Критерий: навык больше не
   предписывает форму безусловно.
5. **D5 — суженное исключение локальной памяти.** Жанровый пункт
   `basic-memory` снимает только требования к телу канонической заметки
   (`## Observations`, `## Relations`, frontmatter) — правило дата-префикса
   действует; висячая ссылка «see Project Memory» убирается. Критерий:
   фрагмент не противоречит суженному состоянию 2.8.0 и не содержит ссылки
   на раздел, отсутствующий в проекте только с `basic-memory`.
6. **D6 — подтверждаемое развёртывание новых навыков при обновлении.** У
   `ai-sync sync-templates` появляется режим плана (`--plan`), который
   перечисляет файлы к созданию, обновлению и удалению без записи; процедура
   обновления сначала выполняет план и требует подтверждения пользователя
   перед применением, если план создаёт файлы навыков или рабочих процессов
   при уже включённых фичах; текстовые обновления существующих развёртываний
   остаются беззвучными. Критерий: режим плана покрыт тестами, текст навыка
   обновления требует подтверждения перед применением плана с новыми
   файлами навыков.

Изменения текстов правил и шаблонов подчиняются правилу merge-gate: ветка
сливается в `main` только с приложенным сравнением из `ai-standards-evals`.
Повышение версии — шаг человеческого решения о релизе
(`docs/decisions/2026-10-12-release-versioning-human-decided.md`).

## Почему

- D1 использует уже проложенный путь прогрессивного раскрытия вместо копий
  по адаптерам: один источник, один развёрнутый путь, который агенты уже
  читают (`.ai-standards/references/`), и дефект 2.6.0 не повторяется для
  нового адаптера.
- D2 устраняет нормативный конфликт, а не комментирует одну его сторону;
  Rule Engineering требует явного старшинства там, где живут правила.
- D3 и D4 делают автономную процедуру настраиваемой теми же механизмами,
  которые уже есть в стандартах (ключи манифеста, правила проекта), вместо
  захардкоженной политики проекта в переносимом навыке.
- D5 восстанавливает инвариант, задуманный решением 2.8.0, и убирает ссылку,
  которая рендерится висячей.
- D6 исправляет проблему порядка (развёртывание раньше анонса)
  детерминированным префлайтом вместо наращивания поверхности манифеста.

## Рассмотренные альтернативы

### D1: копии процедуры внутри каталога каждого адаптера

Отклонено: четыре источника правды для одной процедуры; дефект 2.6.0 показал,
что паритет адаптеров вручную не поддерживается.

### D1: вернуть процедуру в `AGENTS.md`

Отклонено: противоречит control-plane инварианту и отменяет принятое
перемещение M1.

### D2: править только `capture-knowledge`

Отклонено: `core/git-workflow` продолжил бы скрывать исключение от любого
агента, работающего автономно без текста навыка под рукой.

### D3: отказываться запускать запуск без `knowledge-capture`

Отклонено: фиксация возможна и ad hoc; блокировка запуска меняет
отсутствующую необязательную фичу на заблокированную задачу.

### D6: ключ отказа от отдельных шаблонов в манифесте

Отложено: добавляет поверхность конфигурации, не устраняя саму
неожиданность; исправление порядка решает заявленное поведение. Вернуться,
если накопятся шумные навыки.

## Последствия

### Преимущества

- Один источник процедуры для четырёх агентов; класс регрессии 2.6.0
  (висячие ссылки навыков) закрыт структурно.
- Нет нормативного конфликта между автономным запуском и правилами
  фиксации/коммитов.
- Автономные запуски исполнимы в проектах с частичным набором фич.
- Обновления больше не могут молча разворачивать навыки, меняющие поведение.

### Издержки

- У `ai-sync` появляется режим плана, у навыка обновления — шаг
  подтверждения: немного больше церемонии при каждом обновлении.
- Ключ `[knowledge_capture] tasks_tree` остаётся агентским, пока ai-sync его
  не потребляет; doctor каталог по нему не проверяет.
- Eval-проверка — обязательное условие слияния, поэтому цикл исправления
  несёт обычную стоимость сравнения.

## Наблюдения

- [decision] Процедура код-ревью становится общим развёртыванием в
  `.ai-standards/references/` gated на `code-review`, на которое ссылаются
  все четыре варианта `standard-code-review`.
- [decision] Стоящее согласие автономного запуска покрывает коммиты, но
  никогда — отправку, и единообразно сформулировано в `core/git-workflow`,
  `capture-knowledge` и навыке `autonomous-task-run`.
- [decision] Фиксация знаний и имя ветки в автономном запуске следуют тому,
  что проект включает и объявляет, с общими значениями по умолчанию в
  текстах навыков.
- [fact] Issue #26 подтвердила все шесть заявленных дефектов; при
  верификации ни один не был отклонён.
