# РЕШЕНИЕ: merge-only-on-explicit-instruction

Английская версия: [2026-10-11-merge-only-on-explicit-instruction.md](2026-10-11-merge-only-on-explicit-instruction.md)

## Статус

Принято — отменяет формулировку порядка приземления в
[[РЕШЕНИЕ: adopt-autonomous-task-run-skill]]

## Дата

2026-10-11

## Контекст

Навык `autonomous-task-run` вышел в 2.8.0 с шагом 9 процедуры «слей ветку в
целевую по стандарту проекта» рядом с шагом 10, запрещающим push без явного
одобрения. Пользователь поймал это на пост-релизном разборе (issue #25):
пункт 10 корректен, пункт 9 — нет. Далеко не каждый разработчик имеет права
на merge в основные линии — `develop` и `main` чаще всего защищённые ветки, —
поэтому автономный запуск не должен заканчиваться слиянием по собственной
инициативе. Работа заканчивается последним коммитом; слияние — приказ
человека, как и push.

## Решение

1. Автономный запуск завершается на последнем коммите рабочей ветки: знания
   зафиксированы, проверки зелёные. Это состояние завершения.
2. Слияние ветки в целевую — и удаление слитой ветки — происходит только по
   явной инструкции человека, исполняемая тогда по стандарту проекта (для
   этой экосистемы — поток `merge-by-standard`).
3. Push сохраняет своё постоянное правило: никогда без явного одобрения
   пользователя, включая `main`.
4. Completion report называет merge и push среди пунктов, ждущих инструкции
   человека, — если мандат запуска уже содержал такой приказ (например,
   промпт, явно приказывающий слияние).

## Почему так

- Приземление чужой работы в защищённую линию — привилегия, а не допущение:
  навык обязан работать у контрибьюторов без прав на merge.
- Это снимает скрытое напряжение с общим правилом, что коммиты, push и pull
  request'ы происходят только по явному запросу; шаг, приказывающий
  автономный merge, оставался единственным его нарушением.
- Конечное состояние — последний коммит, зафиксированные знания, зелёные
  проверки — полностью обозримо и передаёт человеку решение о приземлении со
  всем готовым.

## Рассмотренные альтернативы

### Оставить merge по умолчанию, гейт только на защищённых ветках

Отклонено: агенту пришлось бы предсказывать защиты веток и права, которые
разнятся по репозиториям и меняются со временем; модель прав знает человек,
а не агент.

### Разрешить автономный merge с обязательным отчётом после

Отклонено: радиус поражения приземляется до ревью; `autonomy-boundaries`
относит основные линии к чувствительным зонам, а отмена слияния — не дешёвый
и предсказуемый откат.

### Оставить правилом уровня проекта (локальным для cockpit)

Отклонено: дефект сидит в переносимом тексте навыка; каждый проект-потребитель
унаследовал бы неверное умолчание.

## Последствия

### Польза

- Навык пригоден контрибьюторам без прав на merge и безопасен на репозиториях
  с защищёнными основными линиями.
- Решения о приземлении остаются за человеком — согласовано с дисциплиной
  push и триггерной моделью `merge-by-standard`.

### Компромиссы

- Запуски, раньше заканчивавшиеся «полным приземлением», теперь заканчиваются
  за одну инструкцию до него; человек явно отдаёт приказ о слиянии (и push).
- Сценарию `ATR-001` пришлось закрепить, что merge возможен только потому,
  что его приказал промпт, — добавлен один запрещённый исход для проверки.

## Наблюдения

- [decision] Автономный запуск завершается на последнем коммите рабочей ветки —
  знания зафиксированы, проверки зелёные — никогда слиянием по собственной
  инициативе.
- [decision] Слияние в целевую ветку и удаление слитой ветки — шаги по приказу
  человека, исполняемые по стандарту проекта.
- [fact] Шаг 10 (push) уже был корректен; исправления требовала только
  формулировка приземления в навыке 2.8.0.
