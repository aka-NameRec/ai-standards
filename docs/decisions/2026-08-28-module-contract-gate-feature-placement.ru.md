# РЕШЕНИЕ: module-contract-gate-feature-placement

English source of truth: [2026-08-28-module-contract-gate-feature-placement.md](2026-08-28-module-contract-gate-feature-placement.md)

## Статус

Принято

## Дата

2026-08-28

## Контекст

Черновик контрибьютора `docs/archive/0tkgv0g-module-contract-discovery-gate.md` определяет гейт обнаружения модульных контрактов: перед правкой производственного кода агент обязан выполнить discovery контрактов (Basic Memory — только как индекс, канонические контракты читаются из репозитория), определить покрытие для каждого затрагиваемого файла, повторить discovery по заданным триггерам, добавить контрактную заметку в отчёт и не трогать код до завершения discovery. Черновик вырос из переписки с контрибьютором (28.07.2026) по растущему проекту, где контракт модуля существовал, но агент не читал его перед правками, и где сам факт настройки Basic Memory не означал, что агенты им пользуются.

Пробел, который закрывает черновик, реален. Сегодня контракты покрыты двумя слоями: политика создания (`structured-artifacts` — что такое контракт и когда его писать) и проверка на ревью (`code-review`, скилл стандартного ревью — сверка изменённых модулей с контрактами после написания кода). Ни одно правило не обязывает агента находить и применять контракты в момент написания кода.

При разборе черновика возник вопрос размещения: если учёт модульных контрактов — фундамент, то почему бы не встроить гейт в существующий раздел Module Contracts фрагмента `structured-artifacts`, вместо отдельной фичи? Эта запись отвечает на вопрос и фиксирует размещение.

## Решение

Гейт выходит как отдельная opt-in фича `module-contract-gate` с фрагментом `process/module-contract-gate`. В `structured-artifacts` он не встраивается.

Проекты включают его одной строкой в списке `features` файла `ai.project.toml`, по договорённости — сразу после `structured-artifacts`. Порядок рендера следует порядку списка фич в манифесте, поэтому раздел встанет непосредственно после Module Contracts — та смежность, о которой просил контрибьютор, достигнутая без правки фундаментального фрагмента. Фичу можно подключить в реестре как композит, указывающий и на `process/structured-artifacts`; дедупликация фрагментов уже корректно обрабатывает проекты, включившие обе.

Продвигаемый фрагмент сохраняет строгое правило черновика почти дословно и адаптирует остальное для общего стандарта:

- Task Start пропорционален: дешёвая проверка «объявляет ли проект какие-либо контрактные артефакты» может завершить discovery отрицательным результатом; обязанность сообщить, когда индекса нет и требуется прямое сканирование, сохраняется.
- Шаги Basic Memory условны — только при включённом Basic Memory; Basic Memory остаётся индексом, канонические контракты читаются из репозитория.
- Обязанность остановиться при противоречии контракту ссылается на стоп-условия `autonomy-boundaries`, а не повторяет их.
- Отчётность — одна короткая контрактная заметка в итоговом резюме реализации, а не второй отчёт.

## Обоснование

- Собранные инструкции плоские: каждая строка включённого фрагмента достаётся всем, кто его включил. `structured-artifacts` включён широко, поэтому встроенный туда гейт стал бы обязательным для всех через рутинное обновление стандарта — без правки манифеста, без согласия, без выбора, видимого в CHANGELOG. Реестр фич существует именно затем, чтобы тяжёлые процессные изменения были opt-in (прецеденты: `code-review`, `autonomy-boundaries`, `chroma`).
- Task Start гейта ссылается на индекс контрактов. Проект с включённым `structured-artifacts`, но без `basic-memory`, получил бы инструкцию проверять индекс, которого там быть не может, и сообщать о его отсутствии в каждой задаче — текст, указывающий на механику, которую проект не разворачивал, сжигающий токены ровно тем способом, от которого черновик пытается защитить.
- Два фрагмента отвечают за разные обязанности: `structured-artifacts` — про создание артефактов, гейт — про потребление при правке кода. Зависимость односторонняя — гейт предполагает политику контрактов, политика без гейта полноценна, — и граница фичи выражает одностороннюю зависимость естественно.
- Необкатанный механизм должен настраиваться и откатываться точечно по проектам. Повысить обкатанную фичу до базового фрагмента потом дёшево; вынуть правило из широко включённого фундаментального фрагмента, на который проекты уже опираются, — дорого.

Предсказуемость не зависит от размещения. Фундамент — три уже существующих слоя: контракты создаются для значимых модулей, они каноничны, ревью их enforce'ит, — плюс недостающий слой момента написания, который добавляет гейт. Включение фичи восстанавливает полный стек на уровне проекта.

## Рассмотренные альтернативы

### Встроить гейт в раздел Module Contracts фрагмента `structured-artifacts`

Отклонено — по четырём причинам из раздела «Обоснование». Решающая — первая: размещение в широко включённом фрагменте превращает выбор процесса отдельного проекта в безмолвное значение по умолчанию для всех потребителей.

### Обеспечивать следование контрактам только на ревью

Отклонено как единственный механизм — это статус-кво. Проверка на ревью видит нарушения контрактов после того, как они написаны; гейт существует, чтобы агент вообще не написал нарушающий код. Механизмы дополняют друг друга, а не исключают.

### Включать гейт по умолчанию во всех проектах со `structured-artifacts`

Отложено до решения о workflow обновления стандарта. Новые фичи могут рекомендоваться в момент обновления с подтверждением по каждой, но включение остаётся явным действием проекта; безмолвное включение при обновлении вернёт проблему, зафиксированную здесь.

## Последствия

### Польза

- проекты выбирают свою процессную нагрузку; обновление стандарта ничего не меняет для проекта, который не подключил фичу
- зависимость от Basic Memory выражена там, где ей место, — условным текстом и выбором в манифесте
- гейт может итерироваться и откатываться по проектам до любого повышения до базового фрагмента

### Компромиссы

- чтобы получить гейт, нужно добавить одну строку в манифест; проект, обновляющийся вслепую, нового не получит. Ровно для этого шага далее определяется workflow обновления, делающий его видимым и дешёвым.

### Дальнейшие шаги

- продвинуть черновик в фичу `module-contract-gate` (размещение принято здесь; реализация впереди)
- определить workflow обновления стандарта — что делает голый запрос «обнови ai-standards»: обновление включённых фич, дайджест новых фич с момента зафиксированной версии, подтверждение по каждой перед включением. Отдельная запись решения последует.

## Observations

- [decision] Гейт обнаружения модульных контрактов выходит как opt-in фича `module-contract-gate`, а не как расширение `structured-artifacts`.
- [decision] Строгое правило гейта сохраняется почти дословно; Task Start становится пропорциональным, а шаги Basic Memory остаются условными — при включённой фиче.
- [fact] Порядок разделов собранного `AGENTS.md` следует порядку списка `features` в манифесте, поэтому гейт встаёт сразу после Module Contracts, если указан сразу после `structured-artifacts`.
