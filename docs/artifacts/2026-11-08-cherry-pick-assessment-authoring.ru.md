# Рабочий лист: авторинг skill cherry-pick-assessment и task spec

Английская версия: [2026-11-08-cherry-pick-assessment-authoring.md](2026-11-08-cherry-pick-assessment-authoring.md)

Рабочий лист Rule Engineering (SE-002) и task spec для issue #27, этап 1.
Написан до начала реализации; требования — константа работы.

## Цель

Выпустить skill `cherry-pick-assessment` как развёртываемый стандартами
шаблон: read-only процедура предварительной оценки переноса, которая
разрешает заявленные пользователем селекторы в подтверждённый упорядоченный
набор SHA и выдаёт вердикт PASS / REVIEW / STOP со свидетельствами,
неизвестными обстоятельствами и конкретным следующим действием.

## Вне объёма

- Никакого исполнительного навыка: никакого фиксируемого cherry-pick,
  разрешения конфликтов с записью в цель, merge, push, rebase или reset.
- Никакого утверждения релиза и никаких изменений регламентов QA/QC/AF.
- Никакой реализации раннера сценариев (исполнение относится к
  `ai-standards-evals`, issue #18).
- Никакой числовой оценки риска.

## Рабочий лист (вердикты Rule Engineering)

| Кандидат | Вердикт | Примечание |
|---|---|---|
| Селекторный вход: идентификаторы задач, merge request, ветка-источник, диапазон, явные SHA, смеси | принят | Устраняет класс ошибок ручного перечисления SHA; у каждого селектора детерминированный механизм разрешения по Git или названный внешний источник |
| Двухфазный вход: навык разрешает селекторы, предъявляет список, пользователь подтверждает до анализа | принят | Сохраняет строгую привязку срока действия к SHA/порядку/HEAD цели (пункт 5 issue #27) без ручного перечисления хешей; подтверждение наблюдаемо |
| Полнота сопутствующих: исправления/откаты с тем же идентификатором задачи входят в кандидатский набор; набор может только расширяться | принят | Операционализирует анализ B issue #27; молчаливое усечение — наблюдаемый антипаттерн (сценарий CP-009) |
| Всегда загружаемое размещение через режим раскрытия ссылок (pointer-блок + развёрнутый файл ссылок, решение 2026-11-02) | адаптирован | Первый проект рендерил полный фрагмент inline в `AGENTS.md` (+1 270 байт, 160 байта до бюджета усечения Codex); режим указателей держит always-loaded дельту ~345 байт и детерминирован для всех агентов |
| Неоднозначное разрешение без уточнения пользователем → STOP | принят | Расширяет пункт 2 issue #27 («состав нельзя установить — STOP») на селекторы; никакой интерпретации «по наиболее правдоподобному» |
| Merge-коммиты требуют основной родительской линии, иначе STOP | принят | Прямое продолжение сценария CP-06 |
| Явные SHA проверяются (существуют в истории источника, subject выводится) | принят | Защита от опечаток и вставки из чужого репозитория без запрета экспертного пути |
| Анализы A–F с классами зависимостей подтверждено/вероятно/непроверено | принят | Дословно из issue #27; каждый анализ называет наблюдаемые выходы |
| Приоритет вердиктов STOP > REVIEW > PASS и коды причин (например `ALREADY_PRESENT`) | принят | Из пункта 11 issue #27; приоритет наблюдаем |
| Разметка ФАКТ / ГИПОТЕЗА / НЕИЗВЕСТНО; классы проверок выполнено/рекомендовано/недоступно/не найдено | принят | Из пунктов 12 и 9 issue #27; оценивается по тексту отчёта |
| Привязка срока действия и аннулирование при любом изменении набора, порядка или HEAD цели | принят | Пункт 5 issue #27 и сценарий CP-008 |
| Гарантии только-чтения; изолированное пробное применение во временном дереве | принят | Из пунктов 3–4 issue #27 и правил чувствительных зон автономности |
| Числовая оценка риска | отклонён | Альтернативы issue #27: ложная точность без калибровки |
| Включение процедуры в обычный code review | отклонён | Иные триггеры и критерии завершения; issue #27 называет самостоятельную процедуру |

Уникальность: ни одно существующее правило или навык не требует того же
наблюдаемого поведения — `standard-code-review` ревьюит дифф по чек-листу
ревью; `cherry-pick-assessment` судит полноту переноса и смысловую
совместимость набора коммитов против целевого состояния до существования
переноса. Пересечение с `autonomy-boundaries` взаимодополняющее: фрагмент
фиксирует инварианты, навык — процедура их исполнения.

Формы проверки: поведенческие сценарии (CP-001…CP-010), набор триггеров
(TRG-004), структурный pytest (REQ-3) и сравнение с навыком и без него в
`ai-standards-evals`.

## Наблюдения

- [решение] Модель входа — единственное содержательное отклонение от
  проекта issue: селекторы, разрешаемые навыком, плюс обязательное
  подтверждение вместо ручного перечисления SHA; все остальные пункты issue
  переносятся без изменений.
- [решение] Всегда загружаемое размещение следует режиму раскрытия ссылок
  (решение 2026-11-02): pointer-блок в `AGENTS.md`, полный фрагмент
  разворачивается как `.ai-standards/references/features/cherry-pick-assessment.md`;
  inline-рендер первого проекта оставил бы собственный `AGENTS.md` в 160
  байтах от бюджета усечения Codex.
- [факт] Коды сценариев следуют шаблону `[A-Z]{2,5}-\d{3}`
  (`tests/test_rule_map.py`), поэтому CP-01…CP-08 issue отображаются в
  CP-001…CP-010.
