# Dogfooding: skill-engineering создан через Rule Engineering (issue #17)

Статус: завершено (2026-09-21, ветка `rules-change/17-rule-engineering`).
Фаза 6 плана изменений: домен-skill `skill-engineering` создан вместе со
своим авторским содержимым (`skill-authoring`), проведённым через поток Rule
Engineering — обязательное требование dogfooding.

## Метод

Каждая кандидатная идея (внешние практики skill-authoring из названных в
proposal источников плюс собственный опыт развёртывания этого репозитория)
прошла поток: кандидатное поведение → атомарность → interpretation surface →
уникальность относительно существующих правил (`rule_map.toml`) →
переносимость → размещение → наблюдаемое поведение → вердикт. Принятые идеи —
это нумерованные правила авторинга навыка, отображённые как `SE-001`–`SE-009`.

## Структурные решения

- **Один домен-skill** `skill-engineering`, авторинг — его первая секция:
  `skill-authoring` существует как содержимое, а не как отдельный навык,
  по вердиктам 11–12 ведомости.
- **Размещение**: навык загружается только при создании/правке/валидации
  навыков (Context Architecture: повторяемая процедура с узнаваемым
  триггером). Всегда загружаемый слой стандартов не растёт; feature
  `skill-engineering` гейтит деплой и переиспользует `rule-engineering`
  как политическую базу.
- **Расширение реестра карты**: правила могут жить в template-навыках —
  `rule_map.toml` получил опциональное поле `source` (путь от корня
  репозитория с расширением) рядом с `fragment`.
- **Деплой**: три файла-адаптера зарегистрированы для codex, cursor, claude
  и kilo; feature гейтит деплой, как у всех навыков.

## Обзор уникальности и конфликтов

- `SE-004` (progressive disclosure + economy) против `CA-002`: разные
  решения — CA один раз выбирает слой, SE-004 управляет компоновкой внутри
  навыка. Поведенческого пересечения нет.
- Переносимость `SE-006` против свойства переносимости `RE-002`: разные
  объекты (тела навыков против общих правил); конфликта нет.
- Конфликтов не найдено; навык не ссылается на рендеренные правила и не
  добавляет always-loaded содержимого.
