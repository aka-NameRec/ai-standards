# План изменений: прогрессивное раскрытие M4 — reporting reference и CR-010/CR-011 (issue #22)

English original: [2026-09-23-progressive-disclosure-m4-change-plan.md](2026-09-23-progressive-disclosure-m4-change-plan.md)

Change set: `STD-CHANGE-0001` · Ветка: `rules-change/22-m4-reporting-reference` · Дата: 2026-09-23

## Цель

Применить модель размещения context-architecture к деталям Report Shape фичи
`code-review`: триггер, охват, инварианты находки и указатель на форму остаются
всегда загруженными; деталь политики оформления переезжает в деплоимую feature
reference. Сначала — поведенческая верификация: CR-010 и CR-011 покрывают
инварианты, которые отвергнутая попытка M3 показала как нагруженные.

## Объём

- `docs/scenarios/CR-010-report-metadata.md` (+ `.ru.md`) — новый контракт
  поведенческого сценария.
- `docs/scenarios/CR-011-reporting-reference.md` (+ `.ru.md`) — новый контракт
  с двумя вариантами фикстуры (reference присутствует / отсутствует).
- `rule_map.toml` — привязка id сценариев к правилам отчёта
  (RVW-016–RVW-018 и правила маркеров/задачи там, где они отображаются).
- `templates/code-review-reporting.reference.md` — новый; деплой через
  `INFRA_TEMPLATES` в `.ai-standards/references/code-review-reporting.md`,
  гейт на feature `code-review`.
- `templates/code-review-report.md` — получает легенду локализации (русские
  имена заголовков), чтобы соответствие жило там, где его читает агент.
- `fragments/process/code-review.md` — секция Report Shape сжимается до:
  указателя на форму, инструкции читать reference, fallback-порядка,
  инварианта строки версии (дословно, по уроку M3), правила языка.
- `tests/test_ai_sync.py` — обновлённые гарантии и проверки деплоя.
- `ai-standards-evals` — фикстуры, датасеты, скоринг и прогоны для
  CR-010/CR-011 (отдельный репозиторий, тот же id change set).

Вне объёма: core-инварианты, routing-секции (только лёгкая компрессия прозы,
позже), стеки, логика рендерера кроме новой записи в `INFRA_TEMPLATES`,
M5/M6 (отдельные гейтованные ходы).

## Целевая структура

Всегда загружено (фрагмент): триггер, охват, указатель на проходы, отчётность
находки, граница small-fix, указатель на форму + fallback-порядок, строка
версии + fallback + мотивация, правило языка сессии, связи, нормализация.
Reference (деплой, читается при написании отчёта): полная семантика маркеров,
политики секций (`What Was Done`, `How It Was Done`, `Verification`,
`Dependencies`, `Task`), мульти-репозиторные отчёты, место публикации,
повторная отправка.

## Риски и инварианты

- Прецедент M3: изъятие мотивации строки версии из всегда загруженного
  контента остановило её вывод агентом. Поэтому строка, её fallback и её
  мотивация остаются в фрагменте дословно; переезжает только деталь политик
  секций. `test_code_review_fragment_keeps_the_version_line_guarantee`
  сохраняется.
- Reference должна быть подключена к базовому workflow (шаг отчёта во
  фрагменте), а не только к skill `standard-code-review` — голый
  "code review" skill не вызывает.
- Детерминизм скоринга: инварианты CR-010 проверяются механически (строка
  версии, маркеры, наличие секций, язык заголовков); reference-present
  вариант CR-011 добавляет одно отличительное механически проверяемое
  требование.

## Сессионный конверт

- Не цели: без изменения нормативной семантики — то же поведение должно
  получиться за счёт более поздней загрузки, а не постоянной; без слияний
  в `main` с этой ветки.
- Ограничения: merge-гейт (приложенное eval-сравнение), push approval
  hardening (только локальные коммиты), языковые пары документации
  обновляются в том же change set.
- Стоп-условия: eval-сравнение с необъяснённой поведенческой регрессией
  (отвергнуть или перепланировать, по прецеденту M3); противоречия контракту
  формата сценариев.
- Ожидаемые артефакты ревью: change plan (этот файл, EN/RU), пары сценариев,
  обновлённые тесты, отчёты прогонов в `ai-standards-evals/reports/`,
  task record.

## Верификация

1. `uv run pytest` (ai-standards) — включая обновлённые policy-тесты.
2. `uv run ai-sync render --project-root .` идемпотентен; `ai-sync doctor`
   без ошибок.
3. `ai-standards-evals`: `uv run ruff check .`, `uv run mypy`,
   `uv run pytest`.
4. Сравнение baseline vs candidate на наборе сценариев (существующие
   CR-001–009 плюс CR-010/CR-011), включая LLM-судью, отчёты в
   `ai-standards-evals/reports/`. Merge-гейт: без необъяснённых регрессий.

## Итог (записан после реализации)

- Первая кандидатская эпоха провалила eval-гейт: без всегда загруженной легенды
  отчёты fallback-пути (без шаблонов, при русском ambient-контексте) деградировали
  в смешанную форму — тот же класс отказа, что у отвергнутой попытки M3.
  Перепланировано внутри согласованного дизайна: fallback-буллет фрагмента хранит
  минимальную легенду русских имён секций (~230 байт), полная политика — в reference.
- Финальное сравнение (по 2 эпохи на ревизию, с LLM-судьёй): ACCEPT, downgrade'ов
  нет; у CR-010 только вариация формы публикации. Отчёты:
  `ai-standards-evals/reports/20260923-std-change-0001-comparison.md`; отклонённая
  эпоха заархивирована в `reports/archive-std-change-0001-epoch1/`.
- Замеры: секция `Code Review` 7 781 → 5 835 байт; собственный `AGENTS.md`
  61 888 → 60 034 байт. Основной выигрыш остаётся за M5.
- Калибровки скорера в `ai-standards-evals` зафиксированы честно в его README:
  находки об отсутствующем покрытии на тестовых путях не считаются выходом за
  диф; маркер pre-existing распознаётся по исходу, а не дословно; fallback-матчер
  CR-012 судит порядок и полноту, а не заголовки; `collect_runs`/`discover_runs`
  покрывают матричную раскладку.
