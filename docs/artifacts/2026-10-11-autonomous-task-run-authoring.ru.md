# Worksheet авторинга и task spec: skill autonomous-task-run

Английская версия: [2026-10-11-autonomous-task-run-authoring.md](2026-10-11-autonomous-task-run-authoring.md)

Task spec для issue #24, совмещённый с worksheet авторинга по Rule Engineering
(SE-002) и планом слайсов. Написан до начала реализации; требования — константа
исполнения.

## Цель

Выпустить навык `autonomous-task-run` как деплоимый стандартами шаблон:
повторяемую процедуру с узнаваемым триггером для исполнения согласованного
плана от начала до конца — entry gate, слайс-цикл со сверкой по task spec,
неизменяемость требований, stop-условия, фиксация знаний, слияние по стандарту.

## Не-цели

- Никакой реализации раннера сценариев (исполнение — `ai-standards-evals`,
  issue #18).
- Никаких изменений нормативного содержимого `autonomy-boundaries`, кроме
  одной строки-указателя на деплоированный навык.
- Никакого push в remote; прочие фрагменты и features не затрагиваются.

## Worksheet (вердикты Rule Engineering)

| Кандидат | Вердикт | Примечание |
|---|---|---|
| Entry gate из четырёх обязательных условий (одобренный план; верифицируемый task spec; слайсованный план с pre-flight проверкой; контекст репозитория и задачи) | accepted | Ложится на правила артефактов и слайсов `autonomy-boundaries`; отказ без гейта наблюдаем |
| Task spec в формулировке «ADR» | adapted | ai-standards называет этот класс артефактов «task spec»; ADR — проектная форма; в навыке: «task spec (an ADR where the project uses that form)» |
| Сверка слайса с требованиями по его завершении | accepted | Операционализирует локальную переоценку `reasoning-hygiene` и design anchors |
| Исправление дрифта только внутри требований | accepted | Правило дословного служения требованиям; наблюдаемо сценарием |
| Требования — абсолютная константа; без добавления и изменения | accepted | Совпадает с Required Stop Conditions («widening scope → stop, а не новое решение») |
| Требования к тому же не переинтерпретируются агентом | adapted | Пункт 4 пользователя расширен переинтерпретацией — закрывает лазейку молчаливой подгонки смысла |
| Коммиты без запроса одобрения на каждый | adapted | Снабжено прецедентной оговоркой: инструкция работать автономно и есть стоящее одобрение commit-потока; форма сообщений — по стандарту |
| Push никогда без явного одобрения | accepted | Подтверждает кросспроектное правило push-hardening внутри процедуры |
| Stop-условия с подробным отчётом об остановке | accepted | Отчёт называет блокированное требование по id из task spec — верифицируемо |
| Фиксация знаний до слияния; слияние по стандарту; completion report | accepted | Зеркалит запуск #23, который навык абстрагирует |

Уникальность: ни одно существующее правило или навык не требует того же
наблюдаемого поведения — `autonomy-boundaries` и `session-hygiene` задают
инварианты и stop-условия; этот навык — процедура, которая удовлетворяет им
запуск за запуском. Формы валидации: поведенческие сценарии (ATR-001
слайс-цикл, ATR-002 остановка при изменении требований), trigger set (TRG-003),
структурный pytest (REQ-3).

## Наблюдения

- [decision] Приняты две словесные адаптации: «task spec (в проектах с ADR —
  в форме ADR)» ради переносимости и оговорка о стоящем одобрении коммитов,
  сохраняющая совместимость с общим правилом одобрения.
- [fact] Самохостинговый манифест не объявляет агентов, поэтому деплой
  адаптеров проверяется на демо-манифесте (kilo + `autonomy-boundaries`), а
  не в этом репозитории.
