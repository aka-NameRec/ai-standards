# Dogfooding: Rule Engineering на feature code-review (issue #17)

Статус: завершено (2026-09-21, ветка `rules-change/17-rule-engineering`).
Фаза 3 плана изменений
`docs/artifacts/2026-09-19-rule-engineering-change-plan.ru.md`: Rule
Engineering применён к реальному существующему feature — фрагменту
`code-review` и навыку `standard-code-review`.

## Метод

Поток Rule Engineering (feature `rule-engineering`, правила `RE-001`–`RE-006`)
применён к `fragments/process/code-review.md`: декомпозиция на атомарные
нормативные поведения, затем проверки неоднозначности (interpretation
surface), уникальности (lexical / semantic / behavioral overlap),
конфликтов/precedence, уровня абстракции, переносимости и наблюдаемости.
Результат отображён как `RVW-001`–`RVW-032` в `rule_map.toml`, каждый с
однострочным ожидаемым наблюдаемым поведением.

## Декомпозиция

32 атомарных поведения по секциям фрагмента: активация и границы
(`RVW-001`–`RVW-003`), пять проходов проверки плюс пометка ранее
существовавшего (`RVW-004`–`RVW-009`), критерии отчётности находок
(`RVW-010`–`RVW-014`), форма и содержание отчёта (`RVW-015`–`RVW-025`),
исключение для мелких исправлений (`RVW-026`–`RVW-028`), отношения к
линзам/навыку (`RVW-029`) и нормализация (`RVW-030`–`RVW-032`). Навык
`standard-code-review` — упаковка (superset-точка входа), а не дополнительные
нормативные правила; его переписанные правила линз покрыты находками о
пересечениях ниже.

## Находки

- **Атомарность.** Один пограничный случай оставлен целым: проход «Архитектура и конвенции» (`RVW-005`) упаковывает контракты, decision records, карту модулей и конвенцию `(no contract)` в одно правило. Разделение дало бы пять микроправил с общим триггером и без независимых режимов нарушения; единица исполнения ревьюера — проход. Таблица русских переводов едет при `RVW-022` как справочное приложение к правилу языка, а не отдельная норма.
- **Неоднозначность (interpretation surface).** Найдены два осознанных домена суждения: «реалистичные объёмы данных» (`RVW-007`) и граница мелкого исправления до того, как её разрешают списки секции `Fixing While Reviewing`. Оба — настоящая территория контекстного суждения; искусственное сужение дало бы ложную точность. Переписывание не требуется.
- **Уникальность / пересечения.** Рассмотрены три пересечения, ни одно не является дублированием: (1) первый пункт Report Shape и первый пункт Normalization лексически близки, но утверждают разные нормы — воспроизвести форму (`RVW-015`) против «у формы нет другого определения» (`RVW-030`); (2) проход Reuse (`RVW-006`) пересекается с двумя дополнительными DRY-правилами, которые навык переписывает — граница и precedence явно заданы в `RVW-029`, навык по дизайну является упаковкой; (3) правило языка отчёта (`RVW-022`) и feature `response-language-style` управляют разными объектами (документ отчёта против реплик чата).
- **Конфликты / precedence.** Нет. Дефолт отчётности (`RVW-003`) и исключение исправлений (`RVW-026`–`RVW-028`) образуют явную оговорку, а не конфликт; правило места отчёта (`RVW-024`) разрешает сохранение в файл только по запросу.
- **Переносимость.** В общих правилах нет vendor- или harness-допущений; `RVW-032` закрепляет границу, а единственный зависящий от harness вход (развёрнутый файл-пример отчёта) имеет явный фолбэк (`RVW-015`).
- **Наблюдаемость.** У каждого отображённого правила есть формулируемый исход. Назначение валидации: поведенческие сценарии для ядра (`CR-001` → `RVW-006`, `CR-002` → `RVW-014`/`RVW-015`/`RVW-019`, `CR-003` → `RVW-009`), статические policy-проверки для правил формы и нормализации в поздних фазах.

🔵 `fragments/process/code-review.md:1-13` — HTML-комментарий происхождения рендерится в `AGENTS.md` каждого включившего проекта (рендерер отрезает frontmatter, но не HTML-комментарии), помещая source-метаданные в always-loaded контекст — нарушает: Context Placement (`RE-006`), оставлено как есть: перенос происхождения в отрезаемый frontmatter меняет контракт рендерера и требует отдельного решения; кандидат на последующую фазу.

## Вывод

Изменения правил не требуются: фрагмент уже удовлетворяет девяти свойствам на уровне проходов — ожидаемо, поскольку он нормализован решением 2026-08-06, предвосхитившим несколько требований Rule Engineering (правило доказательности, запрет накрутки, фиксированная форма). Фаза 3 доставляет декомпозицию, отображение `RVW-*` и первые три поведенческих scenario-контракта (`docs/scenarios/CR-001`–`CR-003`, оба языка), связанных с картой policy-тестами.
