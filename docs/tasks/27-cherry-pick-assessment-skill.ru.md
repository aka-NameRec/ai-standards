# Задача 27: skill cherry-pick-assessment, этап 1

Английская версия: [27-cherry-pick-assessment-skill.md](27-cherry-pick-assessment-skill.md)

Этап 1 issue #27: ADR, рабочий лист Rule Engineering / task spec, сам навык
(четыре формы адаптеров), проводка в реестры и развертывание, записи карты
правил и контракты поведенческих сценариев. Ветка
`feature/27-cherry-pick-assessment`; исполнение сценариев относится к
`ai-standards-evals` (issue #18) и по просьбе пользователя сознательно не
начиналось.

## Что сделано

- **Decision record** `docs/decisions/2026-11-08-add-cherry-pick-assessment-skill.md`
  (+ `.ru.md`): read-only навык предварительной оценки переноса с
  селекторной моделью входа — пользователь называет идентификаторы задач /
  merge request / ветку-источник / диапазон / явные SHA; навык разрешает их
  в упорядоченный список SHA, включает доказуемые сопутствующие коммиты,
  предъявляет список с HEAD цели и продолжает анализ только после
  подтверждения пользователя. Вердикты PASS / REVIEW / STOP с приоритетом
  STOP > REVIEW > PASS, дисциплина свидетельств ФАКТ/ГИПОТЕЗА/НЕИЗВЕСТНО,
  привязка срока действия к подтверждённому набору и HEAD цели.
- **Рабочий лист/task spec** `docs/artifacts/2026-11-08-cherry-pick-assessment-authoring.md`
  (+ `.ru.md`): девять требований с критериями приёмки, вердикты Rule
  Engineering (две принятые адаптации, два отклонения), план срезов и карта
  «issue → контракт» сценариев (CP-01…CP-08 → CP-001…CP-010, поскольку
  шаблон ID в policy-тестах — `[A-Z]{2,5}-\d{3}`).
- **Навык** `templates/cherry-pick-assessment/` в трёх формах адаптеров
  (SKILL.md для codex/kilo, `.cursor.mdc`, `.claude.md`); тела адаптеров
  байт-в-байт совпадают с каноническим телом SKILL.md. Новый раздел «Input:
  Selectors, Resolution, Confirmation» несёт двухфазную модель входа;
  анализы A–F, правила вердиктов, дисциплина свидетельств и обязательная
  форма отчёта следуют issue #27.
- **Размещение**: feature `cherry-pick-assessment` зарегистрирована в
  `registry.toml` (фрагмент `process/cherry-pick-assessment`) и добавлена в
  `[reference_disclosure].features`; собственный манифест включает её в
  `features` + `reference_features`, поэтому `AGENTS.md` рендерит авторский
  pointer-блок (`.ai-standards/references/features/cherry-pick-assessment.md`
  разворачивается через `sync-templates` для всех агентов). Полный фрагмент
  не рендерится inline — inline-рендер первого проекта оставил бы
  `AGENTS.md` в 160 байтах от бюджета усечения Codex 32 768 байт.
- **Регистрация развертывания** в `scripts/ai_sync.py` `AGENT_TEMPLATES`
  для codex, cursor, claude, kilo с gating по новой feature.
- **Карта правил**: `CPA-001`–`CPA-012` в `rule_map.toml`, привязанные к
  секциям шаблона навыка; комментарий префиксов обновлён.
- **Сценарии**: контракты поведения `CP-001`…`CP-010` + набор триггеров
  `TRG-004`, каждый EN + RU. CP-009 (разрешение селектора предъявляет весь
  набор с сопутствующими) и CP-010 (неоднозначный селектор без уточнения →
  STOP) — новые относительно issue; остальные отображают CP-01…CP-08 issue.

## Ключевые решения

- Селекторный вход с обязательным подтверждением заменяет ручное
  перечисление SHA (запрос пользователя при ревью); шаг подтверждения
  сохраняет строгую привязку срока действия.
- Всегда загружаемое размещение следует режиму раскрытия ссылок (решение
  2026-11-02): pointer-блок в `AGENTS.md` (дельта ~345 байт), полный текст
  инвариантов в развёрнутом файле ссылок и навыке — детерминированно для
  всех агентов без зависимости от активации skill в конкретном агенте.
