# ai-sync doctor: детерминированный аудит дерева знаний

Задача: `0tk9qpd` · Ветка: `feature/0tk9ckw-archive-history-in-docs-tree` · 2026-08-24

Английская версия: [0tk9qpd-ai-sync-doctor.md](0tk9qpd-ai-sync-doctor.md)

Связанное: [0tk9qoy-knowledge-genres.ru.md](0tk9qoy-knowledge-genres.ru.md) · [0tk9qpt-audit-knowledge-tree.ru.md](0tk9qpt-audit-knowledge-tree.ru.md)

## Зачем он существует

Дерево знаний деградирует механически: рендер-вход оказывается внутри
индексируемого каталога, индексатор штампует на него frontmatter, проект Basic
Memory настраивают на корень репозитория, выключают пермалинки. Ни одно из этих
нарушений не требует суждения для *обнаружения* — поэтому обнаружение отдано
коду, выполняется за секунды и может стоять воротами CI. `doctor` — этот код.
То, что требует суждения — классифицировать заметку, выбрать слаг, расщепить
смешанный документ, — оставлено [скиллу аудита](0tk9qpt-audit-knowledge-tree.ru.md);
`doctor` сознательно этим не занимается.

## Что он проверяет

**Рендер-входы** (всегда):

- `override-inside-knowledge-tree` (ошибка) — файл из `local_overrides` лежит
  внутри дерева знаний; индексатор может штампнуть на него frontmatter, и
  следующий рендер выльет YAML в середину `AGENTS.md`;
- `override-carries-frontmatter` — индексатор уже штампнул рендер-вход.

**Здоровье заметок** (файлы внутри дерева знаний):

- `note-without-frontmatter` / `note-without-title` — заметка, которую Basic
  Memory озаглавит по имени файла;
- `note-title-heading-mismatch` — `title` во frontmatter и `# H1` расходятся;
- `note-name-against-convention` — имена файлов в датированных каталогах
  (`domain`, `decisions`, `architecture` по умолчанию; настраивается через
  `[basic_memory] dated_note_directories`) нарушают `YYYY-MM-DD-topic-slug.md`;
- `note-without-observations` / `note-without-relations` — заметка не даёт графу
  ничего запрашиваемого;
- `note-unreadable` (ошибка) — повреждение кодировки вместо падения.

**Проводка индексора** (только при включённой фиче `basic-memory`; конфиг
индексора читается, но не пишется):

- `indexed-repository-root` (ошибка) — проект Basic Memory индексирует корень
  репозитория вместо дерева знаний;
- `knowledge-tree-not-indexed` — на это дерево не указывает ни один проект;
- `permalinks-disabled` — адресация `memory://` и обход графа выключены;
- `other-indexed-repository-roots` — другие проекты индексируют корни
  репозиториев и потому блокируют глобальные настройки индексора.

Ошибки дают ненулевой код выхода; предупреждения — нет.

## Как запускать

```bash
ai-sync doctor --project-root <path>                  # отчёт
ai-sync doctor --project-root <path> --fix            # механическая починка
```

Опции: `--knowledge-tree` переопределяет дерево из манифеста; `--indexer-config`
указывает альтернативный конфиг Basic Memory (по умолчанию
`~/.basic-memory/config.json`); `--override-directory` задаёт, куда `--fix`
переносит misplaced рендер-входы (по умолчанию `ai/`).

**Что делает `--fix`**: выносит рендер-входы из дерева и переприцеливает
манифест, снимает штампнутый индексатором frontmatter, восстанавливает
отсутствующие заголовки и `title`, удаляет опустевшие каталоги. После починки
он повторно прогоняет аудит и печатает остаток. Без git-репозитория предупреждает,
что откат невозможен. После переноса рендер-входа просит выполнить
`ai-sync render`.

**Чего `--fix` не делает**: переименование файлов (осмысленный слаг — это
решение об именовании, транслитерация даёт ровно то нечитаемое имя, от которого
конвенция существует) и правка содержимого заметок. Это работа скилла.

## Когда запускать

- после `ai-sync init-project` — подтвердить, что скаффолд лёг правильно;
- в CI или как pre-commit ворота — код выхода 1 на ошибках делает его
  контрольной точкой;
- после изменения настроек Basic Memory или секции `[basic_memory]` манифеста;
- whenever поиск ведёт себя странно — неверный индексируемый корень и
  выключенные пермалинки — два самых частых тихих отказа.

Это *диагностика*, а не ревьюер: чистый отчёт говорит, что дерево подключено
правильно, а не что его содержимое стоит читать.

## Запланировано на этой ветке

По [решению об архиве](../decisions/2026-08-24-archive-history-in-docs-tree.ru.md)
`doctor` дополнительно начнёт пропускать `docs/archive/**` при аудите заметок и
проверять, что активный `.bmignore` несёт исключение `archive/` — граница это
одна конвенционная строка конфигурации, и потерянная строка иначе молча выльет
транскрипты обратно в граф.
