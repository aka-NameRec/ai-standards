# 0tkgosq — Скилл стандартного code review и проверки контрактов

Английская версия: [0tkgosq-standard-code-review.md](0tkgosq-standard-code-review.md)

Дата: 2026-08-28 · Ветка: влита в `main` (коммиты `1da9e6d`, `23e08c9`; на `main` напрямую — по решению пользователя)

## Триггер

Обратная связь контрибьютора (0tkgl9f, 0tkglwf, 0tkgld1): после появления фичи `code-review` сосуществуют два похожих инструмента, и помнить о необходимости прогнать линзы — источник ошибок. Верификация по фрагментам подтвердила тезисы дословно (code-review покрывает темы линз плюс корректность/архитектуру/отчёт/маркеры; у линз остаются два дополнительных DRY-правила — конвенция окружения и клон-детектор — плюс явный режим fix; CI-гейт — за линзами). Собственный промпт пользователя ожидал проверку по линзам и секции `What Was Done` / `How It Was Done` — которые старое правило опускало для standalone-ревью.

## Что сделано

- **Скилл `standard-code-review`**, гейтится существующей фичей `code-review`, разворачивается на четыре агента (codex, kilo → `.codex|.agents/skills/code-review/standard-code-review/SKILL.md`; claude → `.claude/commands/standard-code-review.md`; cursor → `.cursor/rules/standard-code-review.mdc`). Одна процедура: проходы code-review → полный набор линз, включая оба дополнительных DRY-правила → проверка архитектуры и контрактов → один отчёт фиксированной формы на языке чата. Активаторы: «стандартный code review», "standard code review", «сделай ревью по стандарту».
- **Проход Architecture & Conventions** расширен во фрагменте: изменённые модули сверяются с их `MODULE_CONTRACT.md` (ownership, non-goals, инварианты), с принятыми записями в `docs/architecture/**` и с module map; нарушение цитирует конкретный пункт; существенно изменённый крупный модуль без контракта — замечание `(no contract)`, а не дефект.
- **Секции отчёта всегда включены**: `What Was Done` и `How It Was Done` больше не опускаются для standalone-ревью. Первая — фактическая сводка изменения по diff; вторая — что изменение сделало правильно. Выдуманный rationale исключён; самоочевидному изменению достаточно по одной фразе на секцию.
- **Документация**: в usage-гайд code-review добавлен подраздел о скилле; в usage-гайд review-lenses и отрендеренный `AGENTS.md` — мост для CI (скилл — гейт-надмножество; `review-only` остаётся минимальным сигналом «только чистка»); в README отмечен навык.

## Верификация

95 тестов пройдено (развёртывание четырёх адаптеров, наличие активатора, фрагмент называет `MODULE_CONTRACT.md` и `(no contract)`, шаблон показывает форму ссылки на пункт контракта); рендер идемпотентен; `mypy`/`ruff` чисты; `doctor` — ноль ошибок.

## Сознательно не сделано

- Фрагмент `review-lenses` не тронут — он остаётся источником линзовых правил, которые скилл операционализирует; скилл пересказывает два DRY-правила для самодостаточности и ссылается обратно.
- Новая фича и запись в реестре не создавались: скилл гейтится существующей фичей `code-review` — подключившие проекты получают его без правок манифеста.
- Файлы CI-пайплайнов: репозиторий CI не поставляет; usage-доки описывают гейт.

## Observations

- [fact] Стандартное ревью — надмножество голого триггера: проходы code-review, полный набор линз и проверка архитектуры/контрактов в одном отчёте.
- [fact] Пробелы покрытия контрактами помечаются замечанием `(no contract)`, а не дефектом-находкой.
- [fact] `What Was Done` и `How It Was Done` включены всегда; rationale, которого нет в diff, не выдумывается.
- [fact] Скилл гейтится существующей фичей `code-review` — подключившие проекты получают его без правок манифеста.
