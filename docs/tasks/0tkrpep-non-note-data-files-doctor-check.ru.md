# 0tkrpep — Не-заметочные файлы вне дерева знаний

Русская версия оригинала: [0tkrpep-non-note-data-files-doctor-check.md](0tkrpep-non-note-data-files-doctor-check.md)

Дата: 2026-09-03 · Ветка: `feat/0tkrpep-non-note-files-doctor-check` · Пользовательский issue: [#13](https://github.com/aka-NameRec/ai-standards/issues/13)

## Повод

Пользовательский issue #13: в проекте devcats в `docs/artifacts/**` индексируемого дерева знаний накопились 37 фантомных сущностей (7 PNG-скриншотов, 23 выгрузки CSV, 4 сырых лога, 1 PDF, 2 TXT-образца), а одна выгрузка чата на 152K стоила 276 чанков и ~88 секунд процессорного времени на построение embeddings при каждом reindex. Фрагмент `basic-memory` говорил «сгенерированный вывод лежит вне дерева», но не называл бинарные и объёмные файлы и не упоминал механизм масок, который Basic Memory реально поставляет. Сессии планирования (`0tkrne0`–`0tkrpc0`) сверили утверждения issue с исходниками Basic Memory 0.23.2, отклонили жёсткий барьер индексации как нереализуемый и зафиксировали политику в `docs/decisions/2026-09-03-non-note-data-file-doctor-policy.md`.

## Что сделано

- **Decision record** `docs/decisions/2026-09-03-non-note-data-file-doctor-policy.md` (+ `.ru.md`): универсальный не-Markdown детектор плюс учитываемые индексатором маски вместо списка запрещённых форматов; severity WARNING с блокирующим правилом реиндекса на стороне агента вместо гейта ERROR по exit-коду; upstream-отрицание `!` вне области. Отклонённые альтернативы: гейт ERROR, блокировка на входе, сначала upstream-PR, `docs/archive` как хранилище данных.
- **Инструмент** `scripts/ai_sync.py`: doctor сообщает находку `non-note-data-file-inside-knowledge-tree` (WARNING, без автопочинки) для любого не-Markdown, не-скрытого, незамаскированного файла под деревом знаний; `_matches_indexer_mask` повторяет семантику `basic_memory.ignore_utils.should_ignore_path` (паттерн каталога совпадает с одной компонентой пути на любой глубине, glob'ы применяются по компонентам, `*` переходит через `/`, `!` инертен); маски берутся из `.gitignore` в корне дерева знаний всегда и из глобального `.bmignore` рядом с конфигурацией индексатора под feature-гейтом; объявленные overrides и `archive/` не дублируются.
- **Фрагмент** `tools/basic-memory` (+ отрендеренный `AGENTS.md`): новый бюллетень — бинарные и объёмные файлы индексируются как заметки; хранить их вне дерева или маскировать через `.gitignore` корня дерева либо глобальный `.bmignore`; исключений `!` нет; реиндекс только после тихого `ai-sync doctor`.
- **Документация** `docs/basic-memory-usage.md` (+ `.ru.md`): раздел «Границы дерева знаний» называет двоичные и объёмные данные той же ловушкой, указывает, где лежит `.gitignore` (корень проекта индексатора, обычно `docs/`, а не корень репозитория), документирует причуды масок, чистку фантомных сущностей и разовый reindex после маскирования, а также что `docs/archive` обходится до маскирования; Reindexing Policy ставит каждый явный reindex в зависимость от чистого отчёта doctor.
- **Шаблоны** `audit-knowledge-tree` (все три адаптера): перечисление doctor называет новую находку, классификация получила строку Data file, порядок починки предписывает «вынести или замаскировать», никогда не удалять молча.
- **CHANGELOG**: три записи в `Unreleased` (руководство, находка doctor, скилл).

## Проверки

116 тестов прошли (10 новых: файл данных помечен как WARNING, md-дерево тихо, скрытые записи пропускаются, маски `.gitignore` на любой глубине, глобальный `.bmignore` рядом с конфигом индексатора, `archive/` пропущен, нет дублей для overrides, отрицание `!` инертно, сплошная маска держится, находки никогда не чинятся автоматически); `uv run mypy scripts/` и `uv run ruff check scripts tests` чисто; render идемпотентен; `ai-sync doctor --project-root .` сообщает 0 ошибок без находок нового кода на собственном дереве репозитория (прежние предупреждения гигиены без изменений); дым-тест CLI: PNG под `docs/` помечен, после `docs/.gitignore` с `*.png` дерево тихое.

## Намеренно не сделано

- Без bump версии: подготовка релиза (`bump-version`, пин `meta.toml [release]`, тег) — отдельный шаг; CHANGELOG несёт `Unreleased`.
- Без автопочинки новой находки: перенос файлов данных требует решения человека, согласно non-goals контракта модуля.
- Без изменений upstream Basic Memory: PR с отрицанием `!` оценён (реалистично, средняя сложность, трудность — семантика prune обходчиков) и отложен; принятый подход от него не зависит.
- Push не выполнялся: ждёт явного одобрения.

## Контекст следующей сессии

- Проекты-потребители получают обновления фрагмента и скилла при следующем обновлении стандартов; замаскированные деревья остаются тихими, незамаскированный мусор начинает отмечаться предупреждениями.
- Если upstream-PR с отрицанием когда-либо будет принят, синхронизируйте `_matches_indexer_mask` с новой семантикой `should_ignore_path`, прежде чем принимать маски с `!`.
- TODO подготовки релиза: `bump-version` preview/save и тег релиза по Release Workflow.

## Observations

- [fact] Множество детекции замкнуто без перечисления форматов: любой не-заметочный файл под деревом либо замаскирован (не индексируется), либо замечен не-Markdown детектором.
- [fact] Basic Memory обходит `docs/archive`, пока строка `.bmignore` (`archive/`) не исключит каталог, поэтому архив — не запасной выход для файлов данных по умолчанию.
- [decision] Находка doctor — WARNING плюс блокирующее правило реиндекса на стороне агента; блокирующее намерение живёт во фрагменте, Reindexing Policy и скилле аудита, а не в exit-коде.
- [decision] Поддержка отрицания `!` на стороне upstream отложена; локальный матчер повторяет `should_ignore_path` и должен следовать за любым изменением семантики upstream.
