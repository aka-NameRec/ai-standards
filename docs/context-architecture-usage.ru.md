# Руководство по Context Architecture

Английская версия: [context-architecture-usage.md](context-architecture-usage.md)

Гайд описывает, когда включать feature `context-architecture` и что он меняет
в проекте-адаптере.

## Зачем нужен этот feature

Rule Engineering (`rule-engineering`) завершается выбором слоя контекста, но
сами слои до сих пор не имели формального определения: «always-loaded rule»,
«skill», «reference», «retrieval», «script/tool», «project knowledge» и
«adapter» были фольклорными категориями. Без формальной модели размещения
каждое пополнение по умолчанию сползает в всегда загружаемый текст, и
`AGENTS.md` вырастает в свалку всего, что проект когда-либо знал. Этот feature
фиксирует модель: семь слоёв с назначениями, упорядоченный набор
placement-вопросов и инвариант control plane для того, что вообще может нести
всегда загружаемая инструкция.

## Активация

Включите feature в `ai.project.toml` — обычно сразу после
`rule-engineering`, поскольку он формализует выбор слоя, которым тот поток
заканчивается, — и выполните рендер:

```bash
uv run ai-sync render --project-root /path/to/project
```

Жёстких зависимостей нет; сочетается с `rule-engineering` и любой включённой
retrieval-возможностью проекта.

## Что он меняет

- **Размещение становится проверяемым шагом.** Каждое пополнение стандартов
  или инструкций проекта отвечает на placement-вопросы по порядку, первый
  совпавший слой выигрывает, а тай-брейк явен: предпочитать слой, который
  загружает знание позже, но всё же гарантирует его доставку к нужному моменту.
- **Control plane остаётся control plane.** Всегда загружаемые инструкции
  несут универсальные инварианты, маршрутизацию, обязательные гейты,
  precedence, инструкции обнаружения и минимальные требования завершения —
  никогда операционную деталь конкретных задач.
- **Сокращение под гейтом.** Уменьшение всегда загружаемого содержимого
  выполняется только с поведенчески-сохраняющим сравнением с текущим
  состоянием, чтобы экономия контекста не покупалась потерей поведения.

## Чего он не делает

Он ничего не перемещает сам по себе: включение feature меняет решения о новом
знании и запускает классификационный обзор, но любое физическое сокращение
всегда загружаемого содержимого — отдельное, проверенное изменение. Он не
задаёт исполнение сценариев — поведенчески-сохраняющие сравнения относятся к
спецификации `ai-standards-evals` (issue #18).

## Связь с Rule Engineering

Поток Rule Engineering заканчивается шагом «select context layer»; этот
feature — модель, к которой шаг обращается. Placement-вопросы — формальный
инструмент; поток фиксирует решение. Включение одного без другого оставляет
дыру: инженерия без размещения не знает целевых слоёв, размещение без
инженерии не имеет бара качества для размещаемого.
