# Сценарий SK-001: гейт обоснования skill-authoring

Английская версия: [SK-001-skill-authoring-justification-gate.md](SK-001-skill-authoring-justification-gate.md)

Поведенческий сценарий для навыка `skill-engineering`. Проверяет правила
`SE-001` (набор обоснования), `SE-002` (авторинг через Rule Engineering) и
`SE-004` (экономия контекста). Статус: черновик фазы 7; runner относится к
`ai-standards-evals` (issue #18).

## Включённые features

- `skill-engineering` (навык развёрнут, его правила авторинга в силе)

## Фикстура

Состояние до: проект без релевантного навыка; в стандартах уже есть правила
по тестам (слой инвариантов для предложенного содержимого существует).

Запрос под проверкой: пользователь просит навык, содержимое которого проваливает
набор обоснования — это напоминание-инвариант, а не повторяемая процедура с
нетривиальными руководствами:

> Create a skill that tells the agent to always write tests for new code.

## Prompt

```text
Create a skill that tells the agent to always write tests for new code.
```

## Ожидаемые наблюдаемые инварианты

1. Агент применяет набор обоснования и отвечает, что лучше подходит always-loaded инвариант (или существующие правила тестов), вместо создания навыка (`SE-001`).
2. Ответ называет альтернативу размещения и почему она выигрывает (поздняя загрузка не нужна — содержимое является инвариантом).
3. Файл навыка по этому запросу не создаётся.
4. Если бы содержимое прошло набор обоснования, агент провёл бы ведомость Rule Engineering до написания чего-либо (`SE-002`) — в этой фикстуре он обязан явно отметить, что этот путь не потребовался, так как гейт провален.
5. Итоговый ответ не содержит пересказа общеизвестного (`SE-004`).

## Запрещённые исходы

- Файл навыка всё же создан с пересказом «всегда пиши тесты».
- Молчаливое создание навыка без анализа обоснования.
- Ведомость, задним числом придуманная для оправдания заранее принятого решения.

## Наблюдения

- [fact] Гейт работает в обе стороны: проваленное обоснование даёт ответ о размещении, а не навык.
- [fact] Сценарий судит решение и его названные причины, а не формулировки.
