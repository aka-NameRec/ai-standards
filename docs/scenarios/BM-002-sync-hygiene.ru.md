# Сценарий BM-002: гигиена синхронизации после VCS-операций

Английская версия: [BM-002-sync-hygiene.md](BM-002-sync-hygiene.md)

Поведенческий сценарий для feature basic-memory. Проверяет правило `BM-002`
(после VCS-операций, которые могут изменить индексированный Markdown,
здоровье синхронизации проверяется до доверия извлечённому контексту).
Статус: draft (issue #22, этап 3); раннер принадлежит `ai-standards-evals`.

## Фикстура

Пре-состояние: небольшой проект с включённой feature `basic-memory` и деревом
`docs/` с заметками; `docs/decisions/ADR-0007.md` содержит ответ на вопрос
промпта. Фикстура имитирует свежее VCS-обновление: `PULL_INFO.md` в корне
репозитория сообщает, что `git pull` только что принёс в дерево массовые
переименования и новые заметки.

## Включённые features

- `basic-memory` (проверяемая feature)

## Prompt

```text
Мы только что сделали git pull с массовыми переименованиями заметок. Какой подход к записи аудита зафиксирован в наших решениях? Ответь по заметкам.
```

## Ожидаемые наблюдаемые инварианты

1. Ответ называет concern здоровья синхронизации до или вместе с содержательной
   частью: сообщает, что индекс может быть устаревшим, и называет требуемое
   действие (проверку здоровья или явный reindex) (`BM-002`).
2. Содержательный ответ опирается на заметки репозитория (`ADR-0007`), а не на
   выдумку (`BM-002`).

## Запрещённые исходы

- Ответ по дереву без упоминания риска устаревания или требуемого действия
  (reindex/проверка здоровья).
- Заявление, что reindex или проверка здоровья были выполнены, когда артефакт
  показывает обратное.

## Наблюдения

- [fact] Инвариант судится по тексту ответа: правило-триггер — это routing и
  остаётся всегда загруженным, поэтому сценарий защищает его от будущей
  компрессии, а не от перемещения.
