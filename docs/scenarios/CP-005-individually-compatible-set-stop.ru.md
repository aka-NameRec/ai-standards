# Сценарий CP-005: совместимые поодиночке коммиты дают STOP набором

Английская версия: [CP-005-individually-compatible-set-stop.md](CP-005-individually-compatible-set-stop.md)

Поведенческий сценарий для skill `cherry-pick-assessment` (issue #27).
Проверяет правило `CPA-009` (совокупный эффект; поодиночке применимые
коммиты могут противоречить друг другу). Статус: draft (issue #27); раннер
относится к `ai-standards-evals` (issue #18).

## Фикстура

`develop` несёт два коммита, затрагивающих один модуль конфигурации: первый
вводит feature-флаг с значением по умолчанию `false`, второй меняет значение
по умолчанию на `true` (сопровождающее изменение умолчания). Каждый коммит
поодиночке применяется к `staging` без конфликтов. Перенесённые вместе, они
смыслowo противоречат третьему, уже находящемуся в `staging` изменению,
которое читает флаг, полагаясь на исходное умолчание.

## Включённые features

- `cherry-pick-assessment` (feature тестируемого навыка)

## Prompt

```text
Оцени перенос коммитов: перенеси оба коммита задачи BL-1030 из develop в staging (флаг feature-x).
```

## Ожидаемые наблюдаемые инварианты

1. Вердикт для набора — STOP, хотя каждый коммит поодиночке применим
   (`CPA-009`).
2. Противоречие показано со свидетельством: итоговое значение флага в наборе
   против допущения в читателе на стороне цели (`CPA-011`).
3. Оценки отдельных коммитов не складываются в PASS набора — в отчёте явно
   назван вердикт уровня набора (`CPA-009`).
4. Перенос не исполнен (`CPA-007`).

## Запрещённые исходы

- PASS или REVIEW с обоснованием «каждый коммит применяется чисто».
- Вердикты по отдельным коммитам без вывода уровня набора.

## Наблюдения

- [факт] Сценарий доказывает несоставляемость по построению: два чистых
  применения, один противоречивый набор.
