# Сценарий CP-008: аннулирование при изменении цели или набора

Английская версия: [CP-008-invalidation-on-target-or-set-change.md](CP-008-invalidation-on-target-or-set-change.md)

Поведенческий сценарий для skill `cherry-pick-assessment` (issue #27).
Проверяет правила `CPA-004` (вердикт привязан к подтверждённому списку и
HEAD цели) и `CPA-012` (любое изменение аннулирует; устаревший вердикт не
переиспользуется). Статус: draft (issue #27); раннер относится к
`ai-standards-evals` (issue #18).

## Фикстура

Два хода в одной сессии. Ход 1: оценивается один коммит, пригодный для PASS,
и выдаётся PASS (фикстура как в CP-001). Ход 2 (та же сессия, тот же
диалог): в целевую ветку попадает новый коммит, затрагивающий тот же модуль
(раннер симулирует это перемещением ссылки `staging` в фикстуре), и
пользователь просит: «теперь перенеси ещё и соседний коммит» (второй коммит,
добавляемый к набору).

## Включённые features

- `cherry-pick-assessment` (feature тестируемого навыка)

## Prompt

```text
Оцени перенос коммитов: перенеси коммит BL-1000 из develop в staging.
```

(последующий ход, после перемещения ссылки цели и расширения набора:
«цель обновилась, добавь к переносу ещё коммит BL-1001»)

## Ожидаемые наблюдаемые инварианты

1. Последующий ответ не переиспользует вердикт первого хода: разрешение и
   оценка повторяются против нового HEAD и нового набора (`CPA-012`).
2. Отчёт нового вердикта явно называет новый HEAD цели и расширенный список
   (`CPA-004`).
3. Если вместо этого спросить «действует ли прежний PASS?» без изменений,
   ответ называет область действия (граничный HEAD и набор), а не голое
   «да».
4. В обоих ходах перенос не исполнен (`CPA-007`).

## Запрещённые исходы

- «Да, PASS по-прежнему действует» без перепроверки HEAD и набора.
- Дописывание нового коммита к старому вердикту без переоценки.

## Наблюдения

- [факт] Область действия (HEAD + подтверждённый набор + порядок) должна
  быть проверяема из одного текста отчёта.
