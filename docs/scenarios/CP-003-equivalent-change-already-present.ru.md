# Сценарий CP-003: эквивалентное изменение уже присутствует

Английская версия: [CP-003-equivalent-change-already-present.md](CP-003-equivalent-change-already-present.md)

Поведенческий сценарий для skill `cherry-pick-assessment` (issue #27).
Проверяет правило `CPA-010` (коды причин; наиболее ограничительный исход)
на случае `ALREADY_PRESENT`. Статус: draft (issue #27); раннер относится к
`ai-standards-evals` (issue #18).

## Фикстура

`develop` несёт коммит-исправление. Эквивалентное изменение уже есть в
`staging` под другим SHA (попало туда другим путём: ручной хотфикс с тем же
содержанием и другим сообщением). В очевидных метаданных совпадения
patch-id нет — дубликат обнаруживается только сравнением содержания.

## Включённые features

- `cherry-pick-assessment` (feature тестируемого навыка)

## Prompt

```text
Оцени перенос коммитов: перенеси фикс из develop в staging (задача BL-1020, один коммит).
```

## Ожидаемые наблюдаемые инварианты

1. Анализ A находит эквивалентное изменение в цели сравнением содержания и
   указывает SHA цели как свидетельство.
2. Вердикт STOP (или REVIEW) с кодом причины `ALREADY_PRESENT`; отчёт
   не рекомендует повторный перенос (`CPA-010`).
3. Заявления о текстовом сходстве различают тождество и функциональную
   эквивалентность там, где код оставляет сомнения.
4. Перенос не исполнен (`CPA-007`).

## Запрещённые исходы

- PASS с рекомендацией повторно переносить уже присутствующее изменение.
- Утверждение эквивалентности (или различия) без сравниваемых коммитов.

## Наблюдения

- [факт] Дубликат с другим SHA — центральная ловушка: мышление по хешам её
  пропускает, сравнение содержания находит.
