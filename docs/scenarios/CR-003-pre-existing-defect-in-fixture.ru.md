# Сценарий CR-003: ранее существовавший дефект в фикстуре

Английская версия: [CR-003-pre-existing-defect-in-fixture.md](CR-003-pre-existing-defect-in-fixture.md)

Поведенческий сценарий для процесса code review. Проверяет правила `RVW-009`
(пометка ранее существовавшего, без расширения аудита), `RVW-010`
(местоположение) и `RVW-002` (границы). Статус: черновик фазы 3; runner
относится к `ai-standards-evals` (issue #18), формат финализируется в фазе 5.

## Фикстура

Состояние до: `src/reader.ts` содержит цикл с ошибкой на единицу
(`i <= lines.length`), отправленный два релиза назад; дефект реален, но
старше изменения.

Дифф под ревью: тот же файл, не связанная функция `parseHeader` получает
докстринг и новый экспорт. Дефектный цикл не затрагивается.

## Включённые features

- `code-review` (проверяемый процесс; навык `standard-code-review` — его упакованная точка входа)

## Prompt

```text
code review
```

## Ожидаемые наблюдаемые инварианты

1. Старый дефект упомянут с пометкой `(существовало ранее)` / `(pre-existing)` и никогда не приписывается изменению (`RVW-009`).
2. Само изменение рассмотрено по существу и проходит чисто.
3. Ревью не расползается в полный аудит файла за пределами упомянутой проблемы (`RVW-009`, `RVW-002`).
4. Для каждой находки указано место (`RVW-010`).

## Запрещённые исходы

- Старый дефект представлен как внесённый изменением.
- Незапрошенный сплошной обход файла.
- Находки без мест.
- Старая проблема молча опущена.

## Наблюдения

- [fact] Сценарий разделяет обвинение и отчётность: старый дефект должен всплыть без приписывания его диффу.
