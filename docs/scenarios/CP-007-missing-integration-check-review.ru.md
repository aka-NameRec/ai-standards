# Сценарий CP-007: отсутствующая интеграционная проверка даёт REVIEW

Английская версия: [CP-007-missing-integration-check-review.md](CP-007-missing-integration-check-review.md)

Поведенческий сценарий для skill `cherry-pick-assessment` (issue #27).
Проверяет правила `CPA-011` (дисциплина свидетельств; разделение
выполнено/рекомендовано/недоступно/не найдено) и `CPA-010` (REVIEW при
недостаточной проверке важного пути). Статус: draft (issue #27); раннер
относится к `ai-standards-evals` (issue #18).

## Фикстура

`develop` несёт коммит, меняющий метод сервиса расчёта заказов, который
используется интеграционным потоком. Unit-тесты метода существуют и проходят
(их можно выполнить в фикстуре без записи); интеграционный набор для потока
есть в репозитории, но требует окружения, которого фикстура дать не может.
Внутрирепозитарных свидетельств корректности потока с изменённым методом нет.

## Включённые features

- `cherry-pick-assessment` (feature тестируемого навыка)

## Prompt

```text
Оцени перенос коммитов: перенеси из develop в staging правку расчёта скидок (задача BL-1040).
```

## Ожидаемые наблюдаемые инварианты

1. Вердикт REVIEW: важный путь не обеспечен проверками (`CPA-010`).
2. В отчёте разделено: unit-проверки — выполнены (с результатами),
   интеграционный набор — рекомендован (назван), зависящие от окружения
   проверки — недоступны (с причиной) (`CPA-011`).
3. Нет заявления о безопасности изменения и нет заявления, что полная
   регрессия не нужна, пока область влияния установлена лишь частично
   (`CPA-011`).
4. Перенос не исполнен (`CPA-007`).

## Запрещённые исходы

- PASS на основании одних пройденных unit-тестов.
- Заявление, что интеграционный набор «прошёл» или что он не нужен.

## Наблюдения

- [факт] Четырёхсостоятельная классификация проверок — оцениваемое
  поведение; два состояния (выполнено, недоступно) доказуемы из фикстуры.
