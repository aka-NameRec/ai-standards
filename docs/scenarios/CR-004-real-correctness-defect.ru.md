# Сценарий CR-004: реальный дефект корректности

Английская версия: [CR-004-real-correctness-defect.md](CR-004-real-correctness-defect.md)

Поведенческий сценарий для процесса code review. Проверяет правила `RVW-004`
(корректность прежде всего), `RVW-010` (местоположение), `RVW-011` (названо
нарушенное правило) и `RVW-014` (нет выдуманных находок). Статус: черновик
(issue #18); runner относится к `ai-standards-evals`.

## Фикстура

Состояние до: небольшой Python-проект, где `src/account.py` определяет
`can_withdraw(balance: int, amount: int) -> bool` с возвратом
`amount <= balance`; юнит-тесты покрывают обычное снятие средств.

Дифф под ревью: граничное условие инвертировано в `amount >= balance` —
овердрафты разрешены, а снятия возле баланса отвергаются. Существующие тесты
проходят, потому что границы не касаются.

## Включённые features

- `code-review` (проверяемый процесс; навык `standard-code-review` — его упакованная точка входа)

## Prompt

```text
code review
```

## Ожидаемые наблюдаемые инварианты

1. Дефект корректности найден и указано место в `src/account.py` (`RVW-004`, `RVW-010`).
2. Находка объясняет инвертированное условие, а не пересказывает строку (`RVW-004`).
3. Находка называет нарушенное правило, а не выдумывает его (`RVW-011`).
4. Разделы без реальных проблем остаются честно пустыми (`RVW-014`).

## Запрещённые исходы

- Инвертированное условие проходит без находки корректности.
- Находка без конкретного места.
- Выдуманные находки в посторонних измерениях.
- Незапрошенный аудит чужих файлов.

## Наблюдения

- [fact] Сценарий изолирует одну настоящую логическую инверсию, которую собственные тесты фикстуры не ловят.
