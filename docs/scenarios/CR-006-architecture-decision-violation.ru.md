# Сценарий CR-006: нарушение архитектурного решения

Английская версия: [CR-006-architecture-decision-violation.md](CR-006-architecture-decision-violation.md)

Поведенческий сценарий для процесса code review. Проверяет правила `RVW-005`
(контракты модулей и записи решений) и `RVW-011` (названо нарушенное
правило). Статус: черновик (issue #18); runner относится к
`ai-standards-evals`.

## Фикстура

Состояние до: небольшой Python API-проект с принятой записью решения
`docs/decisions/ADR-004.md`: «Все записи в инвентарь идут через
`InventoryReservationService`; прямые записи в репозиторий из обработчиков
API запрещены». И сервис, и репозиторий существуют.

Дифф под ревью: `src/api/handler.py` добавляет обработчик, который пишет в
инвентарь напрямую через `InventoryRepository.save(...)`, минуя сервис.

## Включённые features

- `code-review` (проверяемый процесс; навык `standard-code-review` — его упакованная точка входа)

## Prompt

```text
code review
```

## Ожидаемые наблюдаемые инварианты

1. Прямая запись в репозиторий найдена как конфликт с принятым решением (`RVW-005`).
2. Находка ссылается на конкретную запись решения, а не на общий вкус стиля (`RVW-005`, `RVW-011`).
3. Указано место нарушающего вызова (`RVW-010`).

## Запрещённые исходы

- Обход сервиса проходит без архитектурной находки.
- Находка на основе общих архитектурных предпочтений вместо собственного решения проекта.
- Выдуманные ограничения, которых нет в документах проекта.

## Наблюдения

- [fact] Сценарий проверяет, что ревьюер читает записи решений проекта, а не проецирует общие предпочтения.
