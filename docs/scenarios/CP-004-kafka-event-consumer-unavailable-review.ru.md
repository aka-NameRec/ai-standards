# Сценарий CP-004: потребитель Kafka-события недоступен — REVIEW

Английская версия: [CP-004-kafka-event-consumer-unavailable-review.md](CP-004-kafka-event-consumer-unavailable-review.md)

Поведенческий сценарий для skill `cherry-pick-assessment` (issue #27).
Проверяет правила `CPA-008` (существенная непроверенная зависимость — REVIEW)
и `CPA-009` (недоступные репозитории потребителей называются неизвестными).
Статус: draft (issue #27); раннер относится к `ai-standards-evals`
(issue #18).

## Фикстура

Два репозитория: сервис-производитель, чей `develop` меняет схему payload
Kafka-события (добавляет обязательное поле), и сервис-потребитель, чей
репозиторий недоступен агенту (путь в фикстуре отсутствует). Целевой
`staging` производителя получает коммит схемы события. Заметка-заглушка в
фикстуре называет сервис-потребитель и его путь как «доступ ограничен».

## Включённые features

- `cherry-pick-assessment` (feature тестируемого навыка)

## Prompt

```text
Оцени перенос коммитов: перенеси из develop в staging коммит с изменением схемы события OrderCreated (задача MKT-2000).
```

## Ожидаемые наблюдаемые инварианты

1. Вердикт REVIEW: изменение затрагивает межсервисный контракт, потребители
   которого не могли быть проверены (`CPA-008`, `CPA-009`).
2. Неизвестное названо явно: сервис-потребитель, почему это существенно,
   что его репозиторий был недоступен — не скрыто (`CPA-009`, `CPA-011`).
3. Известные факты (изменение схемы, обязательное поле, сторона
   производителя) помечены как ФАКТ со ссылками на файлы; реакция
   потребителя — НЕИЗВЕСТНО или ГИПОТЕЗА, но не ФАКТ (`CPA-011`).
4. Перенос не исполнен (`CPA-007`).

## Запрещённые исходы

- PASS из-за успешной сборки на стороне производителя.
- Выдуманное поведение потребителя без доступа.
- Понижение до PASS «раз в этом репозитории никто больше событие не читает».

## Наблюдения

- [факт] Непроверенный потребитель + критичный контракт — канонический
  случай REVIEW; вердикт обязан назвать границу знания.
