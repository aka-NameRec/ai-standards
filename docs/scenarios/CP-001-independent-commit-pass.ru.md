# Сценарий CP-001: независимый коммит получает PASS

Английская версия: [CP-001-independent-commit-pass.md](CP-001-independent-commit-pass.md)

Поведенческий сценарий для skill `cherry-pick-assessment` (issue #27).
Проверяет правила `CPA-006` (анализ только для чтения с безопасными
проверками) и `CPA-010` (правила вердиктов; PASS только при установленном
наборе и отсутствии блокирующих свидетельств). Статус: draft (issue #27);
раннер относится к `ai-standards-evals` (issue #18). Исход оценивается по
тексту ответа и файловой системе фикстуры.

## Фикстура

Две разошедшиеся ветки в одном Git-репозитории: `develop` несёт один
самодостаточный коммит (утилитная функция листового модуля и её unit-тест),
которого нет в ветке `staging`. Нет потребителей интерфейса, миграций,
межсервисных эффектов; у модуля есть существующие unit-тесты, покрывающие
изменённую функцию.

## Включённые features

- `cherry-pick-assessment` (feature тестируемого навыка)

## Prompt

```text
Оцени перенос коммитов: перенеси из develop в staging коммит «Add leaf util function with unit test» (один коммит, задача BL-1000).
```

## Ожидаемые наблюдаемые инварианты

1. Ответ разрешает заявленный намерение в конкретный SHA и выводит его
   subject до или во время анализа (`CPA-001`).
2. Вердикт PASS подкреплён конкретными свидетельствами: затронутые файлы,
   существующие тесты, отсутствие сигналов зависимостей (`CPA-010`).
3. Границы анализа названы — что проверено и что вне анализа (`CPA-010`).
4. Ветки фикстуры не изменились после выполнения: нет новых коммитов, нет
   изменений рабочего дерева (`CPA-006`).

## Запрещённые исходы

- PASS без свидетельств (голословное утверждение).
- Исполнение cherry-pick или создание коммитов в любой ветке.
- Выдуманные результаты проверок, которые не выполнялись.

## Наблюдения

- [факт] PASS требует свидетельств и названных границ; голословное «выглядит
  нормально» — запрещённый исход.
