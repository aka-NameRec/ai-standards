# Update ai-standards

One procedure for keeping a project's ai-standards deployment current. The deployed version is recorded twice: the `ai_standards_version` pin in `ai.project.toml` and the `Generated by ai-standards` header of the rendered `AGENTS.md`. The latest version is the newest release of the ai-standards repository this deployment came from.

## Procedure

1. **Establish the deployed version.** Read `ai_standards_version` from `ai.project.toml`; fall back to the `Generated by ai-standards` header of `AGENTS.md` when the pin is missing.
2. **Establish the latest release.** Locate the ai-standards checkout this deployment is maintained from — the `standards_source` entry under `[metadata]` in `ai.project.toml` when present, otherwise the checkout known to this session; ask when neither is known. Bring the checkout up to date (`git pull`), then read its release version from `pyproject.toml` under `tool.ai-standards`, and say so when the checkout is ahead of its latest tag.
3. **Report an already-current deployment and stop** when the deployed version equals the latest release.
4. **Refresh enabled features silently.** Run `uv run ai-sync render --project-root <project>` and `uv run ai-sync sync-templates --project-root <project>`. Text updates to already-enabled features need no confirmation.
5. **Announce what is new since the deployed version.** Read `[feature_meta]` in the checkout's `registry.toml`: a feature whose `since` is newer than the deployed version is new to this project. One line per feature — what changes for this project, a link to its usage guide under `docs/`, and whether it suits the project's `stacks` list: recommend or advise against, never enable. Cover notable skill and workflow additions from the CHANGELOG sections between the two versions as well.
6. **Ask once.** List the announced features and ask which to enable. Apply only what the user confirms: add each confirmed feature to the `features` list in `ai.project.toml`, keeping related features adjacent — `module-contract-gate` right after `structured-artifacts` — and set `ai_standards_version` to the latest release. Re-run `render` and `sync-templates`.
7. **Verify and report.** Run `uv run ai-sync check --project-root <project>` and `uv run ai-sync doctor --project-root <project>`; report the old and new versions, what was refreshed, what was enabled, and anything the user still owes — for example, restarting the agent so the new `AGENTS.md` is loaded.

## Never

- Never enable a feature without the user's explicit confirmation in this update.
- Never push to any remote as part of an update.
- Never invent features, versions, or usage-guide links; read them from the checkout.
- Never treat a stale pin as silent: when `ai_standards_version` disagrees with the source in use, say so before rendering.

## Report

State the deployed and latest versions, the features refreshed, the features enabled with the user's confirmation, the checks that ran, and the next step for the user — restarting the agent and reviewing the new sections in `AGENTS.md`.
